# 0.12 release notes

## [0.12.5]

- Validate NUL-containing paths before filesystem mutation in all six pathname
  publication APIs ([#54](https://github.com/dragginzgame/ic-host-tooling/issues/54)).
  Previously, an invalid final filename could leave newly created parent
  directories behind. The same typed `BeforePublication` / `InvalidInput`
  failure now occurs before parent creation, staging or callbacks. Valid path
  behavior, descriptor-relative admission and publication semantics are unchanged.
  No consumer migration or package dependency change is required.
- Reject failed Git and version observations before release setup, preparation,
  validation receipt replacement or Cargo publication
  ([#56](https://github.com/dragginzgame/ic-host-tooling/issues/56)). Guards check
  command success before comparing output, including empty clean-status output
  and diff pipelines that still produce the expected hash after a producer fails.
  Existing validation receipts, publication intent and consumer artifacts remain
  available after refusal. Release and publication commands retain their existing
  responsibilities and successful behavior; no migration is required.
- Adopt Shared Tooling 0.3.6 `0604bfd730ec7ec288cd2cfdad217a0d42bf256b`.
  Pre-commit stops when any index-tree observation fails, before refreshing
  working files or staging, even if Git prints the expected tree ID
  ([#55](https://github.com/dragginzgame/ic-host-tooling/issues/55),
  [Shared #106](https://github.com/dragginzgame/shared-tooling/issues/106)).
  The formatting adoption checker requires explicit completion before reporting
  success or deleting evidence, including on Bash 3.2
  ([Shared #103](https://github.com/dragginzgame/shared-tooling/issues/103)).
- The shared Cargo executable installer accepts an explicit `--lockfile` instead
  of `--version`, verifies a single stable crates.io package selection, and
  retains failed builds if that selection changes during installation
  ([Shared #96](https://github.com/dragginzgame/shared-tooling/issues/96)).
  Host's release executable keeps its explicit pin; the new mode is optional.
  Snapshot selection, package versions, lockfile and tool pins are unchanged.

## [0.12.4]

- Select Binaryen/wasm-opt 133 and its reviewed archive digests for Linux x86-64,
  macOS Intel and macOS Apple Silicon
  ([#53](https://github.com/dragginzgame/ic-host-tooling/issues/53)). Prepare it
  with `make install-ic-tools`, then verify with `make ic-tools-check` or the
  complete `make tools-check`. Existing setup/check commands and retained-bundle
  behavior are unchanged; an older selection fails offline admission until
  explicit setup prepares the current pins.
- Adopt Shared Tooling 0.3.4 `169d77b8440568c5200eede971625126181f7bb2`
  guidance. The IC pin matrix remains consumer-owned, outside the shared
  snapshot. Other tool pins, library APIs and Cargo selections are unchanged.
  Host has no production optimizer caller; Shared's Node-based optimizer gate
  remains upstream. See [host qualification](../hosts.md) for native evidence
  ownership and [the handoff](../status/current.md) for local qualification.

  the validation runner repaired in Shared 0.3.3, so that unused runner is not
  added to the snapshot. Library APIs, tool pins and package MSRV are unchanged.

## [0.12.2]

- Adopt committed Shared 0.3.1 `fa452afaa5012866eb1c20820dfa8038c106e7ec`
  ([#51](https://github.com/dragginzgame/ic-host-tooling/issues/51),
  [Shared #101](https://github.com/dragginzgame/shared-tooling/issues/101)).
  Setup now admits the IC platform/catalog and checks Rust/Cargo availability
  before common-tool downloads. Host-tool diagnostics report the failed tool,
  expected version, selected path and repair command.
- Preserve host, IC, Rust and Host release-tool installation ordering after
  preflight. Failed preflight stops before any installation; ordinary checks
  remain offline and do not install tools. Rust toolchain preparation remains
  explicit. Existing bundles, build artifacts, failure evidence, tool pins and
  the four library APIs are unchanged.

## [0.12.1]

- Repair the release prerequisite contract by pinning cargo-edit 0.13.13 and
  installing only `cargo-set-version` through the shared selected-Cargo installer
  ([#48](https://github.com/dragginzgame/ic-host-tooling/issues/48)).
  `make install-tools` now prepares it after the common toolsets;
  `make tools-check` verifies it offline. The individual targets are
  `make install-release-tools` and `make release-tools-check`. The adapter checks
  the selected receipt, binary digest and version before using its absolute path;
  missing or altered installations fail without searching global PATH.
- Pass Make jobserver descriptors to Host-owned Cargo, release and publication
  recipes ([#50](https://github.com/dragginzgame/ic-host-tooling/issues/50)),
  retaining the existing refusal of unsafe Make modes. Shared formatting and
  installer recipes await the upstream fix in
  [Shared #99](https://github.com/dragginzgame/shared-tooling/issues/99);
  this change leaves the adopted snapshot intact.
- Require explicit successful completion before Host's Make, release and
  publication fixtures remove temporary evidence. Bash 3.2 unset-variable errors
  and other premature exits now return failure and retain evidence
  ([#49](https://github.com/dragginzgame/ic-host-tooling/issues/49)).
  Fault injection checks the actual fixture entrypoints for unset variables,
  failing commands, explicit failures and early zero-status exits.

Library APIs, package MSRV and common tool pins are unchanged. Explicit setup
prepares the previously implicit release prerequisite using the declared
development toolchain and preserves existing installations and failure evidence.

## [0.12.0]

### Breaking

- Adopt Shared Tooling 0.3.0 at `88a73139a0f083344c41a6f6f4b5c3a8aca7dc1d`
  ([#47](https://github.com/dragginzgame/ic-host-tooling/issues/47),
  [Shared #98](https://github.com/dragginzgame/shared-tooling/issues/98)).
  `make install-tools` and offline `make tools-check` now run the host, IC and
  Cargo toolsets in that order, stopping at the first failure. This includes
  cargo-sort, cargo-sort-derives and candid-extractor even when a particular
  library check does not invoke them. Host setup always includes ripgrep with
  PCRE2 and cloc; direct installer callers must remove `--with-ripgrep` and
  `--with-cloc`.
- Prepare the declared Rust toolchain, then run `make install-tools` and
  `make tools-check` separately before validation. CI and explicitly selected
  release preflight prepare the same set. Standalone release verification and
  ordinary checks only verify prepared tools. The shared Cargo installer owns
  the manifest formatter, replacing CI's separate global cargo-sort installation.

The common tool pins and four library APIs are unchanged. Existing installations,
builds, release receipts and failed evidence are preserved; no artifact reset is
needed. The minor boundary reflects the setup-command contract change, not a
Rust API migration. Product-specific extensions use the ordered local target
lists described in [local setup](../local-setup.md).
