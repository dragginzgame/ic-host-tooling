# 0.12 release notes

## [0.12.0]

### Breaking

- Adopt Shared Tooling 0.3.0 at `88a73139a0f083344c41a6f6f4b5c3a8aca7dc1d`
  ([#47](https://github.com/dragginzgame/ic-host-tooling/issues/47),
  [Shared #98](https://github.com/dragginzgame/shared-tooling/issues/98)).
  `make install-tools` and offline `make tools-check` now run the host, IC and
  Cargo toolsets in that order, stopping at the first failure. This includes
  cargo-sort, cargo-sort-derives and candid-extractor even when a particular
  library check does not invoke them. Host setup always includes ripgrep with
  PCRE2 and cloc; direct installer callers must remove `--with-ripgrep` and
  `--with-cloc`.
- Prepare the declared Rust toolchain, then run `make install-tools` and
  `make tools-check` separately before validation. CI and explicitly selected
  release preflight prepare the same set. Standalone release verification and
  ordinary checks only verify prepared tools. The shared Cargo installer owns
  the manifest formatter, replacing CI's separate global cargo-sort installation.

The common tool pins and four library APIs are unchanged. Existing installations,
builds, release receipts and failed evidence are preserved; no artifact reset is
needed. The minor boundary reflects the setup-command contract change, not a
Rust API migration. Product-specific extensions use the ordered local target
lists described in [local setup](../local-setup.md).
