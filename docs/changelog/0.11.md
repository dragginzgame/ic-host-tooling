# 0.11 release notes

## [0.11.0]

### Breaking

- Use one `tool::OutputLimits` for capture, executable admission and owned-child
  communication. Replace `CommunicationLimits` and its conversion with
  `OutputLimits`; replace `stdout_bytes: n` / `stderr_bytes: n` with
  `stdout: OutputLimit::Terminate(n)` / `stderr: OutputLimit::Terminate(n)`.
  Wrap finite deadlines in `Some(duration)`; `None` is now available consistently
  on every invocation API. Consumers continue to own deadline policy, including
  choosing finite bounds for version probes.
- Read secondary process failures from `ExecutionError::cleanup: Option<Box<CleanupError>>`
  instead of its former `term_error`, `group_error`, `kill_error`, `wait_error`
  fields. `CleanupError` remains the owner of those causes and cleanup status.
  The original execution failure and evidence remain independently available.
- Invoke generic examples from their owners: `hash_serialized_json` moves from
  tools to artifacts; `inspect_git` and `resolve_tool`
  move from tools to process; `inspect_regular_file`, `inspect_archive`,
  `inspect_artifact`, `inspect_gzip` move to fs. The latter compositions use
  artifact development features. `inspect_response` stays in tools and works
  without `candid-extraction`, using explicit development dependencies.
- Release preparation requires a numbered pending entry; the local adapter no
  longer accepts an unnumbered `Draft`. Numbered preparation and source-bound
  interrupted-release recovery remain supported. Existing receipts and historical
  changelog entries are retained.

### Changed

- Adopt Shared Tooling 0.2.13 at `5864f468d39f8f9d1bd26fca1afe0e20f25f1b5e`.
  Snapshot export/verification rejects supplied or resolved directories containing
  LF/CR before selecting another checkout. Selected Cargo-tool diagnostics identify
  package, version, target, profile and destination. Existing artifacts and tool
  selections are preserved
  ([#45](https://github.com/dragginzgame/ic-host-tooling/issues/45),
  [Shared #95](https://github.com/dragginzgame/shared-tooling/issues/95),
  [Shared #96](https://github.com/dragginzgame/shared-tooling/issues/96)).
- `OutputLimit::Truncate(n)` drains output to completion and forwards every chunk
  to an observer while retaining only the first `n` bytes. `Truncate(0)` allows
  forwarding with no retained output. Each stream chooses its own policy;
  `Terminate(n)` preserves hard overflow and cleanup. Truncated evidence has its
  stream flag set, including when the process otherwise succeeds.
- Version admission, Git observation and Candid extraction reject truncated
  captures before interpreting them as complete output. Other parsers can use
  `ExecutionEvidence::require_complete`; callers retaining a child still own its
  final disposition. No extra reader loop or child lifecycle owner is introduced.
- Process and durable-write error messages include secondary cleanup failures
  alongside the original failure. Process formatting still omits captured output,
  arguments and environment. The primary error-source chain remains intact.

These changes implement the approved maintenance decisions in
[#46](https://github.com/dragginzgame/ic-host-tooling/issues/46).
Blocking child-drop behavior is unchanged. This is a source API migration; no
stored-artifact format, installation reset or compatibility shim is introduced.

For a long build with live forwarding and bounded diagnostics:

```rust
use ic_host_process::tool::{OutputLimit, OutputLimits};

let limits = OutputLimits {
    stdout: OutputLimit::Truncate(64 * 1024),
    stderr: OutputLimit::Truncate(64 * 1024),
    timeout: None,
};
```

Pass these limits to `communicate_child_with_observer`, keeping cancellation,
observer scheduling and child cleanup policy in the consumer.
