# 0.27 migration

## 0.27.7

`ic_host_process::signal::SignalActions` installs an explicitly supplied static
handler for caller-selected Unix signals. Its unsafe installation contract
requires async-signal-safe handlers and exclusive process-global registration
custody. Duplicate signals refuse before effects; partial installation rolls
back earlier actions. Explicit restoration preserves native errors and retries
remaining failures on Drop. No signals, flags, cancellation, threads, deadlines
or shutdown policy are selected by Host.

This reconciles [PR #108](https://github.com/dragginzgame/ic-host-tooling/pull/108)
for [#107](https://github.com/dragginzgame/ic-host-tooling/issues/107) without
changing its implementation or subprocess fixtures. Testkit retains its current
handlers until a containing Host release is published and adopted. The existing
libc dependency becomes Unix-scoped rather than macOS-only; no package is added.

## 0.27.6

`ic_host_tools::icp` shares the narrow command protocol proposed by
[PR #101](https://github.com/dragginzgame/ic-host-tooling/pull/101) for
[#97](https://github.com/dragginzgame/ic-host-tooling/issues/97).
`call_command` preserves a caller-configured executable, environment, working
directory, standard IO and native argument bytes, then adds text/binary-file
arguments and query/update selection. `status_command` adds text/JSON/id-only
status selection. Neither executes a command or admits its executable/version.

`decode_installation_status` interprets null `module_hash` as uninstalled and a
string as installed. Missing, invalid or malformed fields return typed errors;
callers must first establish command success and bound captured input. Full status
reports, credentials, targets, response formats, retries and lifecycle stay local.
No dependency, feature or package-version change is required. Canic and IcyDB
retain their production implementations until a published Host API is adopted.

## 0.27.4

`ic_host_artifacts::batch::validate_labels` rejects the first empty or repeated
label with `BatchLabelError` and zero-based occurrence positions, sharing the
mechanics proposed in [PR #184 — Batch label admission](https://github.com/dragginzgame/ic-host-tooling/pull/184).
It accepts an empty batch and compares labels exactly, without trimming, Unicode
normalization or case folding. Iteration stops at the first invalid entry;
callers keep iteration free of batch effects and complete admission before work.
Build and Testkit retain labels, ordering, batch operations and failure policy.
Their normal implementations remain until published Host adoption; this additive
API introduces no dependency, operation scheduler or lifecycle owner.

`ic_host_text::decimal` provides exact fixed and compact two-place rendering from
[PR #139 — Exact decimal text](https://github.com/dragginzgame/ic-host-tooling/pull/139),
addressing [#138 — Share exact decimal text rendering](https://github.com/dragginzgame/ic-host-tooling/issues/138).
Both accept arbitrarily large unsigned ASCII decimal text, apply caller-selected
power-of-ten scaling and round half up, including integer carries. Leading zeroes
and a trailing point are accepted; signs, whitespace, separators and malformed
fractions return `InvalidDecimal`. Large exponents add no proportional allocation.
Query retains normalization, unit promotion, sentinel handling and raw JSON fields;
its current implementation stays until publication and adoption under
[Query #64 — Adopt exact decimal rendering](https://github.com/dragginzgame/ic-query/issues/64).

`ic_host_text::timestamp` owns Query's pure UTC second spelling and Gregorian
conversion from [PR #142 — Canonical UTC timestamps](https://github.com/dragginzgame/ic-host-tooling/pull/142),
addressing [#140 — Canonical UTC text](https://github.com/dragginzgame/ic-host-tooling/issues/140).
Formatting covers unsigned Unix seconds, including expanded positive years;
parsing accepts canonical text from the Unix epoch through `i64::MAX` seconds.
Fractional seconds, offsets, leap seconds, nonminimal fields and impossible dates
remain rejected. No clock, timezone selection or dependency is added. Consumers
retain freshness, source-time interpretation and error policy. Query's existing
implementation stays until publication and its separately tracked adoption in
[Query #66 — Adopt timestamp and Registry owners](https://github.com/dragginzgame/ic-query/issues/66).

`ic_host_fs::path::validate_physical_directory_allow_missing` checks existing
components without creating directories. Symlinks, non-directories and parent
traversal reject; missing components are permitted. Private-parent preparation
uses this same validator before durable creation, retaining native error kinds
and permissions. Diagnostic prose now describes the shared directory check.
Callers retain empty-path, absolute-path and pathname-content policy, namespace
custody and later effects. This observation does not reserve a directory or
provide root confinement. Native filename tests follow lookup behavior without
assuming that creation and lookup report the same error on every filesystem.
Testkit's read-only bundle checks can adopt after Host publication;
its installation policy and existing implementation remain consumer-owned
([PR #147 — Share read-only physical directory validation](https://github.com/dragginzgame/ic-host-tooling/pull/147)).

## 0.27.3

Unix `durable::validate_non_aliasing` and `write_non_aliasing` share protected
export admission and in-place writing from
[PR #154 — Share non-aliasing in-place export writes](https://github.com/dragginzgame/ic-host-tooling/pull/154),
addressing [#153 — Own non-aliasing in-place export writes](https://github.com/dragginzgame/ic-host-tooling/issues/153).
Resolved-name and inode checks run before parent creation; pathname and retained
descriptor checks run again before truncation. Existing permissions and unrelated
symlink destinations are preserved. Native causes remain available through
`NonAliasingWriteError`, distinguishing admission, parent creation, writing and
synchronization failures. A sync failure retains the completely written output.
Callers retain protected-path selection, missing-target symlink depth limits,
namespace/writer custody and recovery. These are in-place writes: they do not
provide atomic replacement, root confinement or parent-directory durability;
errors can leave visible partial output. Query adoption remains tracked in
[Query #69 — Adopt published Host non-aliasing export writes](https://github.com/dragginzgame/ic-query/issues/69).

`ic_host_fs::durable::publish_symlink_with` admits a caller-selected absolute
target before replacing its selection through an unused staging symlink.
Admission or pre-publication failures preserve the old selection and attempt
to remove only the observed staging link. Failures after rename retain the new
selection and report `NamedWriteError::AfterPublication`; reconcile before retry.
Observed foreign staging replacements remain untouched, with cleanup failures
retained alongside the original cause. Panics or failure to observe a newly
created link can leave staging for caller reconciliation.
Consumers retain immutable bundle contents and durability, directory custody,
pins, downloads, permissions, retry and retained-bundle cleanup policy.
This prepares [PR #180 — Share admitted durable symlink publication](https://github.com/dragginzgame/ic-host-tooling/pull/180)
for [#121 — Extract retained tool-bundle publication](https://github.com/dragginzgame/ic-host-tooling/issues/121).
Canic's installer adoption remains separate from this producer change.

Process group execution accepts caller cancellation, explicit cleanup and an
optional shared absolute deadline through the existing bounded engine.
`capture_group_command_with_cancellation` selects piped output;
`run_group_command` preserves configured IO, including inherited build progress
and file-backed streams. Invalid limits, initial cancellation and expired absolute
deadlines refuse before modifying or spawning the command. When both relative and
absolute deadlines are selected, the earlier one applies; `None` adds no deadline.
Consumers retain executable/environment choices, budgets, success requirements
and recovery. Original failures and separate cleanup evidence survive.
The existing capture APIs retain their contracts. This prepares the producer API
from [PR #99 — Share controlled group capture](https://github.com/dragginzgame/ic-host-tooling/pull/99);
Build and Testkit adoption remains separate from Host delivery
([#95 — Expose cancellable group capture](https://github.com/dragginzgame/ic-host-tooling/issues/95)).

Saved-source context requires exactly one parsed object per selected member.
Ambiguous successful parser streams refuse before setup without publishing
context or changing release metadata. Publication retrieval selects SHA-1 or
SHA-256 from the admitted commit identity, independent of `GIT_DEFAULT_HASH`.
The two source-evidence adapters remain until equivalent canonical helpers are
delivered and qualified; refresh both callers and retire both copies together
([#191 — Keep source-evidence adapters hash-format independent](https://github.com/dragginzgame/ic-host-tooling/issues/191)).

Release preparation and retained-evidence mechanics now use Shared's canonical
helpers at `e0b6478a6f0a557b75caeb3e23e34cff6589a9fd`, contributed in
[Shared PR #283 — Share release metadata preparation and retained evidence custody](https://github.com/dragginzgame/shared-tooling/pull/283)

## Consistent text columns

Tables now use the same sum of Unicode scalar widths as clipping and progress
erasure. Joined emoji, presentation sequences and script ligatures follow that
single rule, so table padding can differ from earlier sequence-aware rendering.
For example, `👩‍💻` counts as four columns across all three surfaces.

Update expected table spacing when comparing rendered reports. Clipping remains
UTF-8 safe with its existing streaming behavior; grapheme boundaries and a
particular terminal's glyph rendering are not guaranteed. Control escaping,
ASCII/CJK/combining-character behavior and progress erasure remain unchanged.

## Filesystem identity ownership

Import `FileIdentity` from `ic_host_fs::identity` rather than
`ic_host_process::custody`. Consumers that named the Process type need a direct
FS dependency with the coordinated Host version. Process custody still accepts
and returns the same native device/inode observation; no compatibility reexport
is provided.

`FileIdentity::from_file` still requires a regular descriptor.
`FileIdentity::from_metadata` observes any Unix file kind, allowing filesystem
callers to share identity extraction while keeping their own kind admission.
Native metadata and descriptor stat comparisons use one filesystem owner.

The `device` and `inode` fields retain their values and meaning. Persisted
consumer records do not need a format change. Identities do not freeze contents,
prevent reuse after descriptors close, or establish confinement. Process retains
regular-sidecar checks, locking, spawn allowance, waiting and quiescence policy;
filesystem publication retains file-kind and link-count admission.

Backup's command-lifetime lock must update its import when adopting this release.
Query and Backup can also reuse metadata identity extraction without transferring
their pathname, file-kind or recovery rules to Host.

## Dynamic bordered tables

`ic_host_text::table::render_bordered` accepts a header slice and dynamic rows,
escapes every cell and renders left-aligned ASCII borders. It shares column
measurement and padding with plain tables, including this release's scalar-width
contract. Missing cells are empty and extra cells create unnamed columns.
Header-only output retains its separator; zero columns return empty text.
Bordered cells retain their whitespace and the result has no final newline.

The plain fixed-column API retains its array cell storage and existing row-local
trailing-whitespace trimming. Both APIs leave value interpretation, row budgets,
terminal admission and writing to consumers. IcyDB can use the bordered API for
CLI reports while retaining SQL value semantics and report composition
([PR #129 — Share dynamic bordered tables](https://github.com/dragginzgame/ic-host-tooling/pull/129)).
