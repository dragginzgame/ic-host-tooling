# 0.27 migration

## 0.27.3

Saved-source context requires exactly one parsed object per selected member.
Ambiguous successful parser streams refuse before setup without publishing
context or changing release metadata.

Publication source retrieval selects SHA-1 or SHA-256 from the admitted commit
identity, so an opposite `GIT_DEFAULT_HASH` cannot reject retrievable source.
The publication fixture requires the explicit object-format argument.
The two source-evidence adapters remain necessary until equivalent Shared
helpers are delivered. Canonical adoption must refresh both helpers, update
both callers and remove both local copies together, preserving release and
publication refusals and retained evidence
([#191 — Keep source-evidence adapters hash-format independent](https://github.com/dragginzgame/ic-host-tooling/issues/191)).

## 0.27.2

Shared Tooling 0.24.0 is selected at
`cab12cd3dfa4fdb34846b25397f0d72881bb9ae0`. Production-role annotations retain
global ordering across formatting hooks, CI and release source qualification.
Prepared and committed payload checks enforce ordering on their selected root
manifest, independently of newer working files. Normal/build graph exclusions
select an explicit supported host target and include combined Tools features.
There is no current test-only external dependency set or Host deployment command;
downstream artifact admission remains consumer-owned, as described in
[host qualification](../hosts.md#dependency-exclusions-and-deployment-evidence).

Common Cargo setup now activates cargo-sort and cargo-sort-derives. Host invokes
no native Candid extractor and therefore adds no product extractor selection;
retained installations remain intact. Run `make install-rust-tools` to refresh
an older common-tool activation before `make tools-check`.
The source-evidence helpers in
[Shared PR #269 — Share Cargo source evidence](https://github.com/dragginzgame/shared-tooling/pull/269)
are absent from the released baseline. Their selected-source and archive-provenance
behavior is retained in explicit Host adapters, preserving release/publication
admission while the main snapshot adopts canonical 0.24.0 payloads.
No Rust API, dependency version, lockfile selection or package version changes.

`ic_host_fs::cache_tag::ensure` recognizes the fixed-width `CACHEDIR.TAG`
signature without reading arbitrary trailers. Valid regular tags remain unchanged;
missing, invalid or symlink entries use durable replacement without following
final symlink referents. Callers select exact suffix bytes and permissions.
The existing durable pathname writer creates missing parents with ordinary
directory semantics, preserving Build's cache-initialization behavior. Private
root admission, namespace custody and maintenance remain consumer-owned.
[PR #183 — Own cache-directory tag recognition and durable replacement](https://github.com/dragginzgame/ic-host-tooling/pull/183).

`ic_host_fs::durable::SharedFileLock::acquire` consumes an already-opened regular
descriptor and obtains a blocking shared lock, without selecting a deadline.
Drop explicitly unlocks before closing, so duplicates or inherited descriptors
cannot prolong the guard's lock. Independently opened holders remain separate;
unlock failure falls back to closing the owned descriptor. `file()` borrows the
locked descriptor; callers coordinate any explicit unlock or mode changes.
Build retains shared record lifetimes, namespace custody, cache maintenance and
cleanup, and adopts after Host publication and consumer qualification.
[PR #174 — Extract scoped shared descriptor lock](https://github.com/dragginzgame/ic-host-tooling/pull/174).

`ic_host_tools::candid::decode::decode_one` admits reply bytes and debits a
caller-owned aggregate allowance before decoding. `DecodeLimits` selects reply,
decoding/skipping work, type-table and header bounds without product defaults.
Oversized or aggregate-refused replies leave the allowance unchanged; admitted
malformed or incompatible replies consume it. Errors retain the original Candid
cause. Extra wire arguments follow Candid's compatibility/skipping rules, while
trailing undecodable bytes reject. Consumers retain authentication, schemas,
domain errors and quota selection. Byte/work limits are not a heap, stack or
elapsed-time guarantee.
[#188 — Centralize bounded Candid reply decoding](https://github.com/dragginzgame/ic-host-tooling/issues/188)
and [PR #189 — Add bounded Candid reply decoding](https://github.com/dragginzgame/ic-host-tooling/pull/189).

CI and Make integration checks use the native-host and pipe-jobserver observers
from the existing pinned Shared revision. Host retains its runner matrix,
macOS major selection, PATH setup and actual Make routing assertions. Generic
observer implementation and synthetic tests stay with Shared; this adoption
changes no executable pins, package dependencies or library interfaces.

Read-only and ordered-sync tree hashing share bounded file hashing, digest
collection, error projection and final checksum composition. The sync visitor
still runs hooks before each sync, synchronizes files before hashing, and
synchronizes directories after their children. Exact checksum framing and stored
records remain unchanged. The released `&OwnedFd` walker/checksum/visitor
interfaces and the `&File` sync interface remain supported without caller edits.

`durable::copy_from` remains the stream-copy entry point, including exact
permissions applied after copying. Source admission, byte/time bounds, namespace
custody and recovery remain caller-owned. There is no consumer migration for
these internal cleanups.

Regular and no-follow read/hash paths share descriptor metadata admission,
retaining opening flags, special-file refusal, early size admission and bounded
stream checks. Root-relative opening errors retain messages and native sources.
Bordered tables avoid an all-left alignment allocation with unchanged output.

`ic_host_fs::read::directory_logical_size` supplies the metadata-only walker from
[PR #173 — Extract logical directory-size observation](https://github.com/dragginzgame/ic-host-tooling/pull/173).
It sums non-directory logical lengths without following final symlinks, counting
hard-linked paths separately and saturating at `u64::MAX`. It reads no content,
selects no traversal budget and supplies neither confinement nor a snapshot.
Callers retain namespace custody, resource admission, cache policy and cleanup.
Build adoption remains under
[Build #42 — Simplify batch phases and relocate filesystem mechanics](https://github.com/dragginzgame/ic-build/issues/42)
after publication and consumer qualification.

## Consistent text columns

Tables now use the same sum of Unicode scalar widths as clipping and progress
erasure. Joined emoji, presentation sequences and script ligatures follow that
single rule, so table padding can differ from earlier sequence-aware rendering.
For example, `👩‍💻` counts as four columns across all three surfaces.

Update expected table spacing when comparing rendered reports. Clipping remains
UTF-8 safe with its existing streaming behavior; grapheme boundaries and a
particular terminal's glyph rendering are not guaranteed. Control escaping,
ASCII/CJK/combining-character behavior and progress erasure remain unchanged.

## Filesystem identity ownership

Import `FileIdentity` from `ic_host_fs::identity` rather than
`ic_host_process::custody`. Consumers that named the Process type need a direct
FS dependency with the coordinated Host version. Process custody still accepts
and returns the same native device/inode observation; no compatibility reexport
is provided.

`FileIdentity::from_file` still requires a regular descriptor.
`FileIdentity::from_metadata` observes any Unix file kind, allowing filesystem
callers to share identity extraction while keeping their own kind admission.
Native metadata and descriptor stat comparisons use one filesystem owner.

The `device` and `inode` fields retain their values and meaning. Persisted
consumer records do not need a format change. Identities do not freeze contents,
prevent reuse after descriptors close, or establish confinement. Process retains
regular-sidecar checks, locking, spawn allowance, waiting and quiescence policy;
filesystem publication retains file-kind and link-count admission.

Backup's command-lifetime lock must update its import when adopting this release.
Query and Backup can also reuse metadata identity extraction without transferring
their pathname, file-kind or recovery rules to Host.

## Dynamic bordered tables

`ic_host_text::table::render_bordered` accepts a header slice and dynamic rows,
escapes every cell and renders left-aligned ASCII borders. It shares column
measurement and padding with plain tables, including this release's scalar-width
contract. Missing cells are empty and extra cells create unnamed columns.
Header-only output retains its separator; zero columns return empty text.
Bordered cells retain their whitespace and the result has no final newline.

The plain fixed-column API retains its array cell storage and existing row-local
trailing-whitespace trimming. Both APIs leave value interpretation, row budgets,
terminal admission and writing to consumers. IcyDB can use the bordered API for
CLI reports while retaining SQL value semantics and report composition
([PR #129 — Share dynamic bordered tables](https://github.com/dragginzgame/ic-host-tooling/pull/129)).

## Contributor fixtures

Release-adapter fixtures copy the adapter's declared dependency closure through
Shared Tooling's script-fixture helper. Declare direct inputs on the adapter;
Shared companions carry their own transitive dependencies. Product stubs,
assertions and retained failure evidence remain local. No executable-tool pins
or installation requirements change in this snapshot refresh.
