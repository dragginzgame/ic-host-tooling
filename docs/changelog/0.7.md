# 0.7 release notes

Release dates and draft status are recorded in the [root ledger](../../CHANGELOG.md).

## 0.7.2

### Checkout path handling

Host-owned release helpers, feature checks and qualification fixtures anchor
relative entrypoints before resolving physical directories. An inherited
`CDPATH` cannot redirect resolution or add a second output line. A non-newline
suffix preserves legal trailing newlines in paths. Publication removes only
Git's terminating record newline from its checkout-root observation
([#23](https://github.com/dragginzgame/ic-host-tooling/issues/23)).
The existing adapter fixtures cover relative/absolute invocation from a
newline-bearing tooling root; publication fixtures exercise a newline-bearing
workspace and inspect evidence files without parsing line-oriented log paths.

### Shared Tooling refresh

The snapshot selects committed Shared Tooling 0.1.27
`b866d41041a1986eeec95bde9af4c6ba0853d2e3`, including canonical entrypoint
repairs ([shared #67](https://github.com/dragginzgame/shared-tooling/issues/67))
and dotted snapshot-name recognition in tooling counts
([shared #69](https://github.com/dragginzgame/shared-tooling/issues/69)).
The selection grows from 68 to 72 files to include the installer fixtures'
evidence test, selector, archiver and composite action. The exporter does not
yet declare every new fixture dependency; Host selects them explicitly
([shared #73](https://github.com/dragginzgame/shared-tooling/issues/73)).

Installer fixtures exercise compact successful-tool evidence, full retention
for failed or changed selections, and the collector shell body with substituted
payloads ([shared #66](https://github.com/dragginzgame/shared-tooling/issues/66),
[#68](https://github.com/dragginzgame/shared-tooling/issues/68)). Adopting the
action as a fixture dependency does not wire new artifact uploads into Host CI.
Rust APIs, dependency selections and package versions are unchanged.

## 0.7.1

### Shared Tooling refresh

The snapshot now selects committed Shared Tooling
`75a8a60f49cec11d3f6aecab5c977029c42cc549` (0.1.26), preserving the existing
68-file selection and direct release policy. Dirty upstream edits are excluded.

After confirmed direct delivery or completed resume, the runner updates only
the matching configured remote-tracking ref. Its transaction preserves changed,
symbolic, newer or divergent observations and unrelated upstream mappings;
failure to refresh local status never authorizes repeating an already delivered
push ([shared #62](https://github.com/dragginzgame/shared-tooling/issues/62)).

The canonical exporter can advance an unchanged uncommitted snapshot after
proving its prior bytes/modes against the recorded source. Selected worktree,
path identity, manifest and index changes are refused. Explicit `--add-file`
selections validate required companions; there is no force-overwrite option or
automatic file-set expansion
([shared #60](https://github.com/dragginzgame/shared-tooling/issues/60),
[#64](https://github.com/dragginzgame/shared-tooling/issues/64)).

Tooling LOC reports now include `bin/` and repositories awaiting their first
commit, retaining explicit bootstrap identity and corruption refusals
([shared #61](https://github.com/dragginzgame/shared-tooling/issues/61)).
These are compatible maintained-tooling changes; Rust APIs and dependency
selections are unchanged. Detailed headings in this minor line carry only the
version, avoiding a second draft-status label that the release runner does not
own or finalize. Prior released content is retained.

## 0.7.0

### Shared communication with caller-owned children

`tool::communicate_child` uses the existing capture engine with an already
spawned `OwnedChild`. It writes borrowed input and drains available output pipes
fairly with nonblocking IO, bounded output and a caller-selected deadline. There
are no reader/writer worker threads. Output not configured as a pipe retains the
caller's inherited/file/null policy and is not captured or byte-limited
([#5](https://github.com/dragginzgame/ic-host-tooling/issues/5)).

Callers supply a prompt cancellation predicate; Host owns no global signal
handler or cancellation service. Execution failures close owned pipes and retain
the original failure, bounded evidence and separate group/kill/reap errors.
Invalid deadlines leave the existing child and its pipes untouched. The timeout
starts when communication begins, not at earlier caller-owned spawning. Spawn,
post-IO admission and synchronous cleanup remain explicit timing boundaries.

`SuccessfulExit::Cleanup` signals the owned group before reaping when leader
exit is observed. `SuccessfulExit::Retain` reserves a successful leader through
IO completion so the caller can validate bytes and recheck cancellation/deadlines
before explicitly choosing `handoff`, ordinary `wait`, or `terminate`. Merely
observing successful output never transfers background lifecycle ownership.
Unsuccessful leaders always retain cleanup semantics. Group signalling is not
proof of descendant exit or containment of escaped processes.

`Some(input)` requires a piped stdin, including an empty input. `None` closes
an available stdin pipe; inherited stdin remains caller-selected. Early stdin
closure is accepted so command diagnostics/status remain primary. Success does
not prove all supplied input was consumed or an external effect completed.
Consumers keep input allocation limits, decoding, signals, network readiness,
receipts, retries and recovery. No new dependency, unsafe boundary, background
controller or stored format is introduced.

Existing `capture_command`, `capture_group_command` and admitted-tool execution
share this engine while preserving their existing IO and cleanup selections.
The Query bridge rehearsal can remove its blocking IO workers and supervision
loop. This is isolated evidence against a previously withdrawn candidate, not
adoption in Query's current working tree; actual integration and native
qualification remain distinct in the [handoff](../status/current.md).

### Breaking failure-category changes

Update exhaustive matches for `ExecutionFailure::Cancelled` and
`ExecutionOperation::{StdinPipe, WriteInput}`. Remove references to
`ExecutionOperation::{StdoutPipe, StderrPipe}`: absent output pipes now represent
caller-selected IO for communication, while capture entrypoints always create
their own pipes. These public enum changes require the pre-1.0 minor release.
The canonical error and evidence owners remain unchanged; no compatibility
error model or parallel runner is added.
