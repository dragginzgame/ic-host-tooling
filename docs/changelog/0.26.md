# 0.26 migration

## Explicit cleanup attempts

Consuming `ic_host_fs::owned_directory::OwnedDirectory::cleanup()` performs one
removal attempt. A failure returns its original I/O cause without a hidden second
attempt during Drop. A directory may already be partially removed when the
operation fails; retain its path before consuming the guard and explicitly decide
whether to retry, preserve evidence or report recovery to the operator.

Borrowed `try_cleanup()` still disarms only on success. An armed guard remains
armed on failure for later Drop cleanup. Ordinary armed Drop still makes a best-effort
attempt; explicit `preserve()` and `disarm()` still transfer custody to the caller.
There is no data-format migration, dependency-version bump or compatibility alias.

When a guard must remain borrowed, call `disarm()` before `try_cleanup()` to
transfer recovery before attempting removal. Failure preserves the disarmed
state; no additional cleanup API is needed.

IC Build's failed-build cleanup consumes the guard and already retains its path
and original failure. It now receives the result of exactly one removal attempt;
any later retry belongs to Build's recovery policy. Other Build transaction
callers use `try_cleanup()` or ordinary Drop and retain those semantics.

## Publication preparation

Host delegates archive VCS checks and exact source retrieval to the canonical
Shared Tooling helper. It passes its metadata-admitted package/version/path set
explicitly. Evidence lives under the admission attempt's `provenance/` directory;
inspect its source request, per-package JSON, Git logs and fresh source store
when reconciling preparation failures. Host's existing locks, license policy,
final source check, dry-run contract and publication recovery remain local.

Filesystem error derives preserve the original public variants and source-chain
identity, including the separate write and cleanup causes for scratch files.

## Dependency compatibility

Host Tools 0.25.1 already supplies the compatible `thiserror ^2.0.18` requirement
for consumers selecting PocketIC 16.1.0's exact `thiserror =2.0.18`. The new FS
derives retain that shared floor; Host's own selected lock version need not be
downgraded. The minimal Tools/PocketIC graph and all five Host libraries with
Testkit 0.50.0 resolve using published packages without source overrides
([#178 — Host thiserror minimum conflicts with PocketIC](https://github.com/dragginzgame/ic-host-tooling/issues/178)).

## Bounded copies

`ic_host_artifacts::artifact::copy_gzip` decodes one member into a caller-owned
sink while computing its decoded identity. Compressed and decoded allowances
remain explicit. Truncation, CRC/length errors, concatenated members and trailing
bytes refuse success, even after bytes reach the sink. Sink errors retain their
original cause through `GzipError::Decode(ArtifactError::Io)`; that variant does
not distinguish reader from writer I/O. The operation never flushes or publishes.
Callers own trusted compressed-input admission and private output staging
([#170 — Stream bounded gzip payloads into caller-owned sinks](https://github.com/dragginzgame/ic-host-tooling/issues/170)).

`ic_host_fs::durable::copy_verified` admits a regular source, streams within the
selected byte allowance and checks the expected digest before durable publication.
It follows source symlinks and uses explicit `WriteOptions`; it does not select a
trusted path, freeze source contents, rehash a retained destination or decide reuse.
Digest/source/limit failures preserve prior destination bytes. The existing
`NamedWriteError<CopyError>` contract retains producer, publication and cleanup
failures, including the already-visible state after a publication sync failure
([#102 — Own digest-verified durable artifact copying](https://github.com/dragginzgame/ic-host-tooling/issues/102)).
