# 0.30 migration

## 0.30.1

Artifacts updates its private wasmparser backend from 0.261.0 to 0.262.0, matching
the existing encoder's optional parser integration and removing the older parser
selection. Host's public inspection and validation APIs are unchanged; parser
diagnostic wording and upstream validation decisions follow the selected backend.
Full instruction/type validation still requires `wasm-validation`; inspection,
encoding-only and text-only production graphs do not enable it. Defaults remain
empty and the supported Rust floor remains 1.88.

Host selects published Platform 0.2.0 through the compatible `0.2` requirement,
with defaults disabled. Host's Agent, Candid/parser, certification and ledger
capabilities retain their existing feature selections and public contracts.
Platform's 0.2 runtime/entrypoint changes do not require a Host source migration:
Host selects neither its `cdk` nor executor/system features, and owns no canister
endpoints. Required external Candid interoperability remains opt-in; default,
certificate-only and interface-only graphs keep excluding Candid's parser.

## 0.30.0

### Explicit filesystem backends

FS 0.29 made its new Unix capability and scoped-tempfile backends unconditional.
That also selected cap-* for Process and ordinary FS/CLI consumers that used
neither API. FS now keeps empty defaults and exposes independent features:

| API | Required feature | Private Unix dependencies |
| --- | --- | --- |
| `ic_host_fs::capability` | `capability` | cap-std, cap-fs-ext |
| `ic_host_fs::scratch::TemporaryFile` | `temporary-file` | tempfile |

For example, consumers of held directory handles select:

```toml
ic-host-fs = { version = "0.30", default-features = false, features = ["capability"] }
```

Select both features if both APIs are used. `cli` and `test-support` select
neither; ordinary reads, publication, locking, caller-retained scratch files and
Process remain available without them. Existing operation semantics and private
backend implementations are unchanged. Both optional APIs remain Unix-only.

Verified source consumers needing migration after the supplying release are
Query's `crates/ic-query/src/cache_file/confined` (`capability`), Testkit Dev's
`crates/ic-testkit-dev/src/fixture_reuse_driver` and IcyDB CLI's
`crates/icydb-cli/src/icp/call.rs` (`temporary-file`). Their checkouts remain
unchanged. Other users should check their imports before adopting this minor.

Normal/build graph checks cover defaults, each backend alone, both together,
CLI, Process and the Wasm inspector. The non-Unix combined graph excludes both
backends. Cargo feature unification can still enable a backend when another
selected consumer requests it, and workspace lockfiles may retain packages
needed by other targets, features or older dependency versions. This change
narrows selected build graphs; it does not promise that every lock entry vanishes.
