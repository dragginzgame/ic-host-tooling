# 0.30 migration

## 0.30.0

FS's Unix `capability` module requires the `capability` feature. The Unix
`scratch::TemporaryFile` guard requires `scoped-tempfile`. Neither feature is
enabled by default, and they are independent of each other and the existing
`cli` and `test-support` features. The backends and observable behavior stay in
the same owner; no implementation or compatibility alias is added.

```toml
ic-host-fs = { version = "0.30", default-features = false, features = ["capability"] }
```

Query's confined cache adapter needs `capability`; IcyDB's named ICP argument
files and Testkit's fixture worker output need `scoped-tempfile`.
Direct callers must enable those features with
their actual published Host adoption. IC Build's existing read/durable/directory
and Process consumers need neither. Their defaults and file CLI graphs exclude
cap-std, cap-fs-ext and tempfile. Optional features remain Unix-only; selecting
them on the unsupported Wasm target introduces no native backend dependencies.

The feature graph matrix covers minimal, each independent backend, their union,
CLI, Process and non-Unix selections. Native CI also runs minimal FS tests and
the existing held-capability and scoped-tempfile regressions independently.
These checks preserve symlink/special-file refusals, bounded enumeration,
permissions, temporary-file lifetime and explicit cleanup errors. Graph
observation and Linux tests do not qualify native macOS execution.
