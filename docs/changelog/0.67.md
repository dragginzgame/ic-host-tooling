# 0.67 release notes

## 0.67.0 - Unreleased

### Build comparison evidence

`ResolvedCargoBuildInputs::recipe_identity()` and
`WasmBuildRecord::recipe_identity()` provide source-independent comparison
identities. They cover observed compiler/Cargo identities, target, profile,
package/example selection, workspace profiles, discovered build configuration
and explicit compiler/build environment settings. Features stay separately
attributable through `facts().selection.features`, allowing deliberate cohort
feature differences.

The digest exposes no raw configuration or environment values. Unrelated
credentials, source bytes, lock/dependency identities and output directories are
excluded. Configuration locations and all declared profile settings are compared
conservatively; equivalent relocated configurations can have different identities.
Wrapper settings are covered, but wrapper executable bytes and arbitrary
build-script inputs are not. Consumers still compare lock identity and their
additional inputs. This identity never replaces the existing cache fingerprint
or source mutation guards.

This supplies the producer API requested by
[#241 — Build: expose source-independent recipe identity for cohort comparisons](https://github.com/dragginzgame/ic-tooling/issues/241).
Timers adoption and downstream cohort qualification remain separate.

### Archive qualification and diagnostics

**Breaking:** `qualify_package_archives` now requires a `&CargoFeatureSelection`
after its package list. Pass `CargoFeatureSelection::default()` to retain the
previous feature policy, or select the intended feature graph explicitly. The
same selection applies to packaging, extracted metadata, target tests and
doctests. The workspace qualifier selects all features while preserving a fresh
attempt-specific target and frozen external package selections.

`PackageCommandError` adds `stage`, `stdout_path` and `stderr_path` fields.
`ConfigurationFile` adds `recipe_sha256`. Code constructing these public structs
must supply the new fields. The package-check command reports the failed stage,
retained log locations and a bounded, terminal-escaped tail of captured output.
Capture and log-retention failures remain independently represented.

### Maintained tooling

- Browser fixture sessions reject nonzero exits after readiness, including
  failed graceful shutdown, while preserving callback and cleanup errors
  ([#242 — Browser fixture sessions can succeed after the fixture exits unsuccessfully](https://github.com/dragginzgame/ic-tooling/issues/242)).
- Testkit crates inherit workspace lint policy, with documented public contracts
  and local annotations for native unsafe operations and intentional lifetimes.
- Native CI caches ordinary workspace compilation directories. Archive
  qualification targets remain fresh. Browser CI cancels superseded runs, and
  publication scripts are included in ShellCheck coverage.
- Cargo input resolution has a private implementation module; existing source
  selection, cache identity and mutation guard contracts remain unchanged.

### Configuration and comparison admission

`observe_configurations` and `WasmBuildSpec::new` now require explicit
`ConfigurationLimits`: per-file bytes, total bytes, file count and include depth.
Configuration reads use Host's bounded regular-file reader. Existing callers must
select their own limits; the library supplies no default configuration budget.
Recipe identity includes ordered include structure, `CARGO_INCREMENTAL` and
`RUSTC_BOOTSTRAP`, while excluding both Cargo output-directory environment aliases.

`compare_benchmark_aggregates` returns `BenchmarkComparisonError` and refuses
duplicate scope/span identities on either side instead of silently keeping the
last row. Average errors remain available through its `Average` variant.

Archive errors display every independent log-retention failure and label paths as
log destinations. Each command records its stage in `current-stage` before launch;
this is retained stage intent, not a completion or success marker.

CI qualifies ICP project, ICP ledger, ledger evidence and YAML features separately
on development Rust and MSRV. Native jobs have explicit outer timeouts. Runtime
failures retain temporary fixtures, command logs and selected product evidence.

### Shared Tooling adoption

Adopt Shared Tooling 0.26.10 at revision
`a8141e775983c7fe504c4dd911e978152e657fdf`. Formatting reads the same literal
tool catalog as installation; tool diagnostics support aggregate offline reports
and read-only selection descriptions. Existing pins and compiler selections remain.

Native CI uses the common action's opt-in Cargo-tool cache, including the local
release-editor recipe in its cache key. Normal setup and admission still run
after restore, with saves restricted to main-branch pushes. Direct dependency
checks select the common external IC inventory; the local policy retains YAML,
FS, Wasm and other stricter restrictions. Duplicate IC prohibitions are removed
from the local policy after common-guard qualification.
