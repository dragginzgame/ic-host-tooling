# 0.16 — Explicit native tooling features

## [0.16.0]

### Breaking

`ic-host-tools` has an empty default feature set. Consumers using
`candid::extraction` must select `candid-extraction` explicitly:

```toml
ic-host-tools = { version = "0.16", features = ["candid-extraction"] }
```

Workspace consumers keep the version in their root manifest and select features
in the child manifest. Response decoding and `candid::text::normalize` remain
available without optional dependencies. `ic-interface` continues to select the
Candid parser and Wasm facts; `ic-limits` selects only Wasm facts. Neither implies
extraction. The APIs retain their 0.15 module paths; there are no compatibility
aliases or implicit extraction fallback.

These crates run on the host. Feature selection here does not remove Candid
encoding needed by a canister's public calls, nor does it choose whether a
canister emits Candid metadata or type-export code. Consumers own that build
choice and may retain development inspection while omitting optional export
machinery from production. No deployed Wasm-size reduction is claimed here.

### Contributor tooling

Adopt Shared Tooling 0.9.13. Authorized development and validation may prepare
missing Cargo sources with `cargo fetch --locked` without another maintainer
approval. Explicit offline settings remain authoritative; dependency upgrades,
executable-tool installation and release effects retain separate authorization
([Shared #147](https://github.com/dragginzgame/shared-tooling/issues/147)).

Retain 0.9.11's fixes: tool-store and checkout locking retain native
filesystem failures and statuses without removing an existing lock. Cargo tool
source-acquisition failures retain their original status and stop before build
or activation, preserving installed tools and evidence
([Shared #145](https://github.com/dragginzgame/shared-tooling/issues/145),
[Shared #146](https://github.com/dragginzgame/shared-tooling/issues/146)).
The changed build-helper identity requires explicit Cargo-tool setup before
offline admission, even though tool versions are unchanged.

Native CI restores Cargo-tool builds using Shared Tooling's canonical build
identity, extended with Host's release-tool pin and installer. Cache transport
has bounded, nonfatal attempts; explicit installation and byte/receipt admission
still run on hits and misses. Only successful setup on main saves a cache. No
broad fallback key, credential cache or checkout tool symlink cache is used.
Linux x86-64 and macOS 15 Intel/Apple Silicon remain required, and newer runs
continue to cancel superseded runs.
