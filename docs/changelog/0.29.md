# 0.29 migration

## 0.29.0

### Shared Tooling 0.25.1 adoption

The snapshot selects committed Shared main
`d57c631206e3618755e45bebf2c88c673564ddc1` (0.25.1). The standalone Perl
manifest/lock renderers are retired. Host's release adapter delegates rendering
to the released IC Build 0.18.0 editor, admitted through the verified tool store.
`ci/release-editor.env` owns the exact tool version and 8-MiB per-document input
allowance. Source custody, member eligibility, receipts, byte comparison,
independent locked graph validation and rollback remain with Host/Shared.

`make install-tools` now includes `install-release-editor`; `tools-check` includes
offline editor admission. No per-shell editor environment export is needed.
Preflight can perform first-use setup after source admission; verification and
saved-plan preflight and recovery checks require the prepared selection and never
install it. Saved-plan preflight also keeps dependency admission offline. The editor
uses the development toolchain and requires Rust 1.91 or later. This does not
change the libraries' Rust 1.88 MSRV. No release or publication is executed by
snapshot adoption or its isolated fixtures.

Both native CLIs and maintained argument-taking examples use Clap. Their paths,
budgets and domain checks remain explicit, including native non-UTF-8 paths.
Supported operation/report bytes and binary refusal status 1 remain unchanged;
help/version and argument diagnostics now use Clap's standard presentation.
**Installation change:** select `--features cli` when installing/running
`ic-host-fs --bin ic-host-file`. Its target and Clap dependency are opt-in;
library defaults stay free of CLI dependencies. The standalone Wasm inspector
still installs normally. Existing install scripts must add the feature before
adopting this Host release. See the [file CLI guide](../file-cli.md).

CI and release validation check indexed and tracked/nonignored working paths for
symlinks. Source package notices remain complete regular copies of the root
license. Upload preparation checks each archive's exact notice and refuses linked
or malformed assets before any upload dispatch. Maintainer artifacts and admitted
tool-store selection pointers are preserved. Host's selected graph matrices use
Shared's canonical checker, with direct backend-owner rules and separate enabled
feature checks retained locally. These observations do not attest deployed bytes.

The Wire preference adds no codec dependency here: Host supplies host utilities
and interoperability helpers, with no owned canister RPC endpoints. Opt-in Candid
service/reply tooling targets external Candid contracts and DID files through
Platform; converting those bytes to Wire would break the required interoperability.

### Filesystem and native adoption

The previously prepared capability and scoped-tempfile APIs are now present in
this checkout. Published 0.28.1 did not integrate those producer changes; its
preparation notes do not establish delivery. Root package versions remain unchanged
until the maintainer executes the supplying release.

FS owns private Unix cap-std/cap-fs-ext dependencies through
`capability::{Directory, FileEntry, DirectoryOptions}` and bounded entry iteration.
Use the [capability guide](../capability-fs.md) to migrate Query's confined readers,
writers and discovery. Query retains cache paths, identities, permission settings,
candidate/depth/aggregate limits, truncation and public errors. Remove its direct
cap-* declarations only after those callers and regressions migrate.

Unix `scratch::TemporaryFile` uses private tempfile allocation for scoped named
files, with existing-parent/prefix admission, private permissions, best-effort drop
cleanup and explicit `close` errors. Retain it through every child using its path.
It provides no disk sync or crash cleanup. `create_private_bytes` remains the
explicit caller-retained alternative; existing successful files keep that custody.
IcyDB already uses this retained API and no longer directly declares tempfile.
Testkit's unnamed capture files and temporary directories remain separate; this
change does not claim that every tempfile use can adopt a named-file guard.

`read::open_regular_file_no_follow` returns a standard read-only descriptor after
final-component NOFOLLOW/NONBLOCK/CLOEXEC and descriptor-based regular-file
admission. It performs no byte read or limit selection. Backup's reference sync
and Canic's lock inspection can replace their repeated native open/fstat blocks;
map `ArtifactError::NotRegularFile` to their existing public refusal and preserve
native IO causes. This follows ancestor links and retains no namespace exclusion;
use held capabilities where ancestor confinement is required. Other native uses
mean those repositories may still legitimately retain rustix.

Testkit's standalone server/driver and Query's governance harness can replace
their saved-sigaction implementations with existing Process `signal::SignalActions`.
The application must exclusively coordinate the selected process-global signals,
retain its async-signal-safe handler and flags, and restore overlapping guards in
reverse order. Keep cancellation, shutdown and child recovery with each caller.
Canic's cooperative signal-hook and terminal restoration are distinct and remain
local; unregistering a callback is not restoration of the previous disposition.
No new signal-hook dependency, facade or implicit signal policy is introduced.

### Optional WebAssembly Text compilation

Artifacts adds `wasm-text` and
`wasm_text::{compile, CompileLimits, CompileError}` using private wat 1.262.0 with
default/component features disabled. Call `compile` with explicit `source_bytes`
and `module_bytes`. Source length is admitted before parsing; complete output
length is checked afterwards. Only core-module output is accepted. The full core
text language supports Backup's stateful fixtures without expanding the narrow
call-only module encoder or creating a local WAT parser.

Compilation alone does not prove type/instruction validity. Select
`wasm-validation` and call `wasm::validate` for that independent proof. Byte
allowances are not CPU or peak-allocation quotas. Owned compiler diagnostics may
contain input excerpts; callers own presentation. No file loading or execution
is added. Defaults, binary inspection and encoding-only graphs exclude wat/wast;
text-only normal/build graphs exclude wasmparser and Host's validator. Cargo's
lock may retain the encoder's optional parser integration even when no selected
profile compiles it; Host's binary inspector still selects 0.261.0.

Backup can replace the two fixture `wat::parse_str` calls with Host `compile` and
remove its direct WAT declarations after adopting the supplying release. Keep its
fixture sources and PocketIC lifecycle in Backup. Query's generated governance
reply module fits Testkit's `pic::fixtures::raw_reply_canister`: adopt that existing
API with `reply-fixtures`, then remove Query's WAT construction and dependency.
Testkit can in turn use the Host encoder/validator described below. This avoids
adding a second shared owner for IC-specific fixture construction. No sibling
source, manifest or lockfile is changed or claimed as migrated here.

### Wasm encoder and validator ownership

Artifacts adds the independent `wasm-encoding` feature and
`ic_host_artifacts::wasm_encoding::{encode, CallModule, FunctionImport, Call,
ExportedFunction, Memory32, DataSegment, EncodingError}`. The private backend is
wasm-encoder 0.262.0, matching Testkit's existing selection and supporting Rust
1.88. Default backend features and optional parser integration are disabled.
Encoding alone adds only leb128fmt transitively; Host's inspector stays at 0.261.0.
Neither default Artifacts nor `wasm` inspection selects the encoder. Encoding
alone does not select the production parser or validator.

The API encodes core Wasm32 with one fixed, exported memory, active data and
exported () -> () functions calling imports with i32 arguments and void results.
Callers supply exact names, calls and data layout. Host rejects invalid import
indices/arity, duplicate exports, invalid memory and out-of-bounds data. The
complete returned module must fit both the caller's byte allowance and u32.
Admission checks obvious input lower bounds before encoding and final framing
afterwards; the allowance is not a peak-heap or CPU quota. No IC policy, arbitrary
opcode interface, execution or lifecycle API is added. The existing custom-section
encoder and its pre-allocation admission remain unchanged.

The opt-in `wasm-validation` feature adds `wasm::{validate, ValidationError}`
and implies `wasm`. It validates types and instructions as well as structure,
with an input-byte allowance and owned errors; structural `inspect` remains
independent. Target/proposal acceptance and installation policy stay with callers.
The previously prepared validator is included here because the released 0.28.1
source did not integrate it. Existing 0.28 notes describe that earlier preparation.

Testkit's `pic::fixtures` is the verified encoder consumer. When adopting the
supplying Host release, map its `reply-fixtures` feature to
`ic-host-artifacts/wasm-encoding`, translate its existing recipe into these Host
records and select an explicit complete-output allowance. Retain IC method-name
admission, query/update prefixes, reply budgets, layout choices and error mapping
in Testkit. Enable `wasm-validation` on its dev dependency and replace both full
validation calls in fixture tests with `wasm::validate`; replacing them with
`inspect` would weaken coverage. Then remove direct wasm-encoder and wasmparser
declarations and verify reply fixture behavior. No sibling adoption is claimed.

### Certificate codec consolidation

Tools' opt-in `certificate` feature uses serde_cbor 0.11.2, the codec already
selected by IC Agent, replacing Ciborium
([#201 — Replace the certificate Ciborium backend](https://github.com/dragginzgame/ic-host-tooling/issues/201)).
This supersedes the unmerged Minicbor proposal. It introduces no direct Minicbor
dependency, fork, generic parser or upstream codec re-export. IC certificates
and encoded witnesses still use CBOR as required by the protocol.

The codec owns recursion and semantic-tag handling. Host removes the adjustable
`DecodeLimits.depth` field instead of recreating that codec policy. This is a
breaking consumer change: inputs above serde_cbor's built-in recursion limit
can now refuse even when the old caller-selected budget admitted them. Semantic
tags also consume the codec's recursion budget. Host keeps its complete-input
byte allowance, checked before parsing, and its separate trailing-data category.

Update certificate callers from:

```rust,ignore
DecodeLimits { bytes: maximum_bytes, depth: maximum_depth }
```

to:

```rust,ignore
DecodeLimits { bytes: maximum_bytes }
```

This applies only to `ic_host_tools::certificate::DecodeLimits`; Candid limits
are unchanged. No fallback or ignored depth setting is retained. Consumers with
their own depth option must explicitly retire it or define a separate application
tree policy; Host no longer promises a caller-selected decoding-depth ceiling.

Owned Platform certificate/hash-tree identities, exact node tags/arities, pruned
digest lengths, strict field admission and byte-string requirements remain.
The small schema adapters are intentional: upstream deserialization accepts
broader byte projections and some duplicate-null fields. Decoder errors retain
a redacted Host wrapper with a private native serde_cbor error source. Decoding
does not authenticate signatures, commitments, delegation or trust roots.

### Dependency and consumer effects

Ciborium, ciborium-io, ciborium-ll and unused half 2.x leave Host's lockfile.
serde_cbor and half 1.x were already selected upstream; existing dependency
versions remain selected. Minicbor remains transitively selected by the optional
ledger profile's upstream crates, independently of certificate decoding.

Defaults remain empty. Certificate-only and certificate/interface normal/build
graphs require serde_cbor and exclude Candid/parser, Agent transport and Minicbor.
Tests cover fixed recursion behavior, semantic tags and valid indefinite byte
chunks against the IC Agent codec, plus independent strict Host schema refusals.

Query is the inspected consumer of the removed depth field. Its certificate and
witness adapters must update their initializers and any public depth policy when
adopting the supplying 0.29 registry release, then refresh their lockfile and run
their authentication/error-projection tests and certificate-host graph checks.
No sibling repository is modified by this change.
