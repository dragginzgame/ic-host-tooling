# 0.29 migration

## 0.29.0

The 0.28.1 package was published before the producer PRs were integrated.
Its preparation notes do not establish delivery of those APIs. This batch
contains the filesystem and Wasm additions alongside the revised codec below;
consumer adoption still requires the supplying release.

### Filesystem and Wasm additions

FS adds Unix directory/file-entry handles using Query's existing cap-* backend
([Host #80](https://github.com/dragginzgame/ic-host-tooling/issues/80)). Root selection
and directory traversal reject symlink components; creation re-admits entries after
AlreadyExists races and synchronizes the held parent. Exclusive file creation,
regular-file opening and unlink/sync operate relative to retained handles.
Removal errors distinguish completed unlink from parent-sync failure.

The [capability guide](../capability-fs.md) describes integration with the existing
bounded reader and durable writer. Callers supply directory permission masks,
creation modes and enumeration ceilings. Cache paths, schemas, identities, file
permission admission, discovery selection, aggregate/depth limits and public error
mapping remain in Query. No Query source or dependency declaration changes here;
its direct cap-* dependencies can be removed after its adapters migrate.

cap-std and cap-fs-ext become private Unix implementation dependencies of FS.
Their absence from non-Unix graphs is checked alongside the existing unsupported
target compile contract; this does not add non-Unix filesystem support.

Enable `ic-host-artifacts`'s `wasm-validation` feature for full core-module
validation via `wasm::validate(bytes, max_bytes)`. This implies `wasm` and selects
the existing wasmparser dependency's validator; no parser, validator, feature-flag
or validated-type identities are re-exported. Errors preserve byte-limit refusal,
unsupported component encoding and an owned invalid-module diagnostic with its
source offset. Input-byte admission precedes parsing/validator allocation and does
not promise CPU or heap quotas.

The implementation validates complete modules, including every function body's
instructions, type consistency and index references, using the selected parser's
default supported proposal set. Existing structural inspection is unchanged and
the `wasm` feature alone does not select the validator. Consumers still own
target-specific feature admission, IC installation policy and deployment.

Testkit's two fixture-test Validator calls can become
`ic_host_artifacts::wasm::validate(&wasm, 100_000).unwrap()` with an explicit
caller-selected allowance and a dev-dependency selecting `wasm-validation`.
After both callers migrate, remove its direct wasmparser dev-dependency and unused
root catalog entry. This Host change does not modify Testkit or claim its adoption;
the supplying Host version must be published first.

Unix FS now owns the tempfile dependency behind `scratch::TemporaryFile` for
short-lived named argument files. Creation requires an existing caller-selected
parent and normal filename prefix, resolves parent aliases and refuses CR/LF
directory paths. The upstream backend owns randomized exclusive allocation and
private 0600 permissions subject to umask. Standard file access and absolute
paths are exposed without leaking upstream types.

Keep the guard alive through child completion. Drop attempts unlink, including
unwinding; consuming `close()` exposes removal errors. No file/parent sync or
crash cleanup is promised. Bytes, budgets, command execution, retries and any
paid-operation recovery remain caller-owned. Use the existing caller-retained
scratch API for files that must survive this scope; directory fixture custody
and its panic-retention policy are unchanged.

IcyDB's `crates/icydb-cli/src/icp/call.rs::call_hex` currently creates a
NamedTempFile, writes wire bytes and retains it through ICP child completion.
After adopting a supplying Host release, it can create a Host TemporaryFile in
its selected parent, write with `as_file_mut()` and pass `path()` to the same
command. Then remove its direct tempfile dependency and unused catalog entry.
This change leaves IcyDB source and dependency selection unchanged.

### Certificate codec consolidation

Tools' opt-in `certificate` feature uses serde_cbor 0.11.2, the codec already
selected by IC Agent, replacing Ciborium
([#201 — Replace the certificate Ciborium backend](https://github.com/dragginzgame/ic-host-tooling/issues/201)).
This supersedes the unmerged Minicbor proposal. It introduces no direct Minicbor
dependency, fork, generic parser or upstream codec re-export. IC certificates
and encoded witnesses still use CBOR as required by the protocol.

The codec owns recursion and semantic-tag handling. Host removes the adjustable
`DecodeLimits.depth` field instead of recreating that codec policy. This is a
breaking consumer change: inputs above serde_cbor's built-in recursion limit
can now refuse even when the old caller-selected budget admitted them. Semantic
tags also consume the codec's recursion budget. Host keeps its complete-input
byte allowance, checked before parsing, and its separate trailing-data category.

Update certificate callers from:

```rust,ignore
DecodeLimits { bytes: maximum_bytes, depth: maximum_depth }
```

to:

```rust,ignore
DecodeLimits { bytes: maximum_bytes }
```

This applies only to `ic_host_tools::certificate::DecodeLimits`; Candid limits
are unchanged. No fallback or ignored depth setting is retained. Consumers with
their own depth option must explicitly retire it or define a separate application
tree policy; Host no longer promises a caller-selected decoding-depth ceiling.

Owned Platform certificate/hash-tree identities, exact node tags/arities, pruned
digest lengths, strict field admission and byte-string requirements remain.
The small schema adapters are intentional: upstream deserialization accepts
broader byte projections and some duplicate-null fields. Decoder errors retain
a redacted Host wrapper with a private native serde_cbor error source. Decoding
does not authenticate signatures, commitments, delegation or trust roots.

### Dependency and consumer effects

Ciborium, ciborium-io, ciborium-ll and unused half 2.x leave Host's lockfile.
serde_cbor and half 1.x were already selected upstream; existing dependency
versions remain selected. Minicbor remains transitively selected by the optional
ledger profile's upstream crates, independently of certificate decoding.

Defaults remain empty. Certificate-only and certificate/interface normal/build
graphs require serde_cbor and exclude Candid/parser, Agent transport and Minicbor.
Tests cover fixed recursion behavior, semantic tags and valid indefinite byte
chunks against the IC Agent codec, plus independent strict Host schema refusals.

Query is the inspected consumer of the removed depth field. Its certificate and
witness adapters must update their initializers and any public depth policy when
adopting the supplying 0.29 registry release, then refresh their lockfile and run
their authentication/error-projection tests and certificate-host graph checks.
No sibling repository is modified by this change.
