# IC Tooling 0.64

## [0.64.1] - Unreleased

### Held provider replies

Opt-in native `held-reply-fixtures` adds a controller and Wasm generator under
`pic::fixtures::held`. Supply bounded single-use update slots with original raw
reply bytes; observe an exact request, commit unrelated ingress, then explicitly
release that request. Multiple pending calls may resolve out of order without
changing their original reply identity. Repeated names consume slots in order;
exhaustion, unknown/repeated releases and cross-instance control refuse.

The barrier uses PocketIC's existing manually mocked HTTP outcalls. Keep manual
progress and fixed simulated time; HTTP timeout or management rejection fails
the original call instead of releasing its configured response. Abandon the
isolated instance on uncertain release or unfinished work. Installation, funding,
protocols and application assertions stay with the consumer. Host owns WAT
compilation; Platform supplies the external management Candid types/encoder on
native targets only. No fixture encoder, Host or Candid enters deployed graphs.

See [usage and lifecycle](../../crates/ic-testkit/README.md#held-provider-replies)
and [#234 — Testkit: support controllable held replies for installed callback-race tests](https://github.com/dragginzgame/ic-tooling/issues/234).
Canic's mounted cancellation/revocation proof remains consumer-owned and requires
adopting the supplying release; this change does not claim that proof is complete.

### Qualification fixtures

The Make routing fixture now expects the held-reply feature profile used by the
actual development/MSRV Wasm checks. This fixes a stale expectation that stopped
release qualification after the feature was added. A failed nested relative-path
fixture now replays its retained log and preserves its original exit status;
parent and child evidence remain available at their reported paths.

## [0.64.0] - 2026-10-22

### Shared Tooling

Adopt Shared Tooling 0.26.6 at `4cb9bc907154225a3f7e4c33fd8d75fbeaa125c8`
through the canonical exporter, retaining the existing entrypoint selection and
adding the CI/release integrity audit. Host, Rust and IC tool pins are unchanged.

Cargo graph checks accept command-line feature annotations when selected roots
overlap. Retained validation logs preserve parent and nested failures, bound
highlight excerpts before shell capture, publish latest logs without following
redirected paths and preserve failure status through summary/cleanup errors.
Checksum admission rejects NUL-bearing backend output; artifact downloads require
exactly one metadata document. Full raw evidence remains retained.

Ordinary expensive integration/native CI now follows the adopted asynchronous
baseline instead of a local cadence exception. Focused checks, enforced GitHub
reviews/checks and independent runtime approval boundaries remain in force;
release/publication/deployment and issue-specific acceptance remain separate.
No workflow dispatch, branch-protection change or executable installation is
part of this refresh. Producer CI and native qualification are reported separately
from this consumer's focused checks.

### Dependency and helper ownership

Import PocketIC clients and DTOs directly from `ic_platform::pocket_ic`, enabling
Platform's `pocket-ic` feature in native test dependencies. Testkit no longer
forwards that module or exports upstream types from `pic`. Its own startup,
lifecycle extensions, snapshots, diagnostics, pooled baselines and Wire calls
remain available. Existing fixtures use the same upstream type identities.

```toml
[dev-dependencies]
ic-platform = { version = "0.6", features = ["pocket-ic"] }
ic-testkit = { version = "0.64", features = ["wire"] }
```

```rust
use ic_platform::pocket_ic::{PocketIc, PocketIcBuilder};
use ic_testkit::{fake_principal, pic::PocketIcStartupConfig};
```

The stateless `Fake` and `performance::Performance` types are removed. Replace
`Fake::principal(seed)` with `ic_testkit::fake_principal(seed)` and
`Performance::measure` / `Performance::counters` with
`ic_testkit::performance::{measure,counters}`. Principal bytes, counter reads,
marker framing and native/Wasm availability are preserved.

Diagnostics batches now return `ic_host_artifacts::batch::BatchLabelError`
directly. Replace `CanisterDiagnosticsBatchContractError::EmptyLabel` and
`DuplicateLabel` matches with `BatchLabelError::Empty` and `Duplicate`.
The index, label and original/repeated positions are unchanged. Host validates
all labels before any diagnostic collection; ordered collect-all behavior and
panic containment remain unchanged. Generic label diagnostics use Host's prose.

Host Tools' aggregate Candid decoder now accepts
`ic_platform::candid::DecodeLimits`. Replace imports of
`ic_host_tools::candid::decode::DecodeLimits` with the Platform type; field names
and values are unchanged. Oversized replies still refuse before aggregate
charging; admitted malformed replies consume their allowance, and decoder quotas
and original typed failures are preserved. No Candid API is added to Testkit.

The forwarding-only Testkit qualification tests are retired. Real local fixture
and lifecycle targets compile against Platform directly. Server provisioning
also delegates generic physical-directory admission to Host FS; Testkit retains
empty-path/newline policy and path normalization. Redirected paths and parent
traversal still refuse before download, now with Host's typed IO causes.

See [#233 — Remove duplicate dependency facades and policy types for 0.64](https://github.com/dragginzgame/ic-tooling/issues/233)
for the consumer review. Sibling checkouts are unchanged and require their own
adoption and qualification; no compatibility aliases are retained here.

### Wire response admission

- **Breaking error precedence:** Testkit's optional Wire calls delegate response
  admission directly to `ic_wire::decode_response`, removing the duplicate byte
  check. Wire first admits the declared response schema and then checks the
  received frame size and contents. An invalid response schema combined with an
  oversized reply now produces `WireCallError::Decode` with `SchemaLimit` rather
  than `Limit`. Update assertions or error matches that rely on the former
  precedence; correct the method's response limits before retrying. Valid method
  contracts, frame bytes, context, received-byte counts and single-dispatch
  behavior are unchanged. The check occurs after PocketIC allocates the reply;
  this does not introduce a transport receive-memory bound
  ([#232 — Delegate Testkit Wire response admission to the Wire decoder](https://github.com/dragginzgame/ic-tooling/issues/232)).
