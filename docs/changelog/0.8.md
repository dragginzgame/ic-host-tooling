# 0.8 release notes

Release dates and draft status are recorded in the [root ledger](../../CHANGELOG.md).

## 0.8.0

### Caller-selected termination timing

`OwnedChild::spawn_with_cleanup` accepts `CleanupPolicy::TermThenKill { grace,
reap_timeout }`. Query can select five seconds for each allowance, preserving
its existing timeout/interruption contract
([#5](https://github.com/dragginzgame/ic-host-tooling/issues/5)). The policy lives
on the existing child owner and is used by explicit `terminate`, communication
failure cleanup and Drop, including unwinding. No second IO loop, signal handler,
background reaper or application lifecycle controller is introduced.

Termination signals TERM to the owned group, waits the selected grace after
successful signalling without reaping the leader, then signals group KILL even
if the leader exited during grace. A TERM failure remains visible while KILL
and reaping are still attempted. Group KILL failure retains the existing direct
child kill fallback. Only the leader is reaped; signalling is not descendant-exit
proof or containment of processes that escape the group.

The reap allowance starts after signalling. Reaping uses nonblocking observations,
including after interruption. A zero allowance permits one observation. Repeated
termination and Drop reuse the original allowance without repeating escalation
or starting another wait period. On expiry, `wait_error` has `TimedOut` and the
unreaped child remains owned. The caller may explicitly recover through
`try_wait` or `wait`; dropping instead may leave an unreaped child until parent
exit. There is no hidden blocking destructor or asynchronous recovery service.
Native syscall latency and scheduling are outside these polling bounds.

Communication retains its original timeout/cancellation/IO failure and bounded
output alongside cleanup diagnostics. Its operation deadline excludes the
separate cleanup allowances. Pipes close before failure cleanup, avoiding an
unbounded drain of inherited writers or blocked stdin.

`OwnedChild::spawn` and existing capture entrypoints retain immediate KILL and
synchronous reaping. Explicit natural waits still clean an exited leader's group
without TERM grace. Successful `SuccessfulExit::Retain` still needs explicit
caller admission followed by `handoff`, waiting or termination; starting bounded
termination disallows subsequent communication or background handoff.

Coverage includes a TERM-exited leader with a TERM-ignoring descendant, blocked
input, descendant-held pipes, timeout, cancellation, explicit termination,
unwinding and successful handoff. Reap-expiry coverage substitutes an already
dispatched escalation around a real running child; it does not induce an
unkillable native task. Native and consumer acceptance remain separate in the
[handoff](../status/current.md).

### Breaking cleanup evidence fields

`child::CleanupError` and `tool::ExecutionError` add `term_error: Option<io::Error>`.
`group_error` describes group KILL, `kill_error` the direct-child fallback and
`wait_error` reaping. Update struct literals and exhaustive destructuring; use
`term_error: None` for existing immediate-KILL fixtures. These public struct
changes require the pre-1.0 minor release. No function, method or type is removed.
