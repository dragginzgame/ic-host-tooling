# 0.8 release notes

Release dates and draft status are recorded in the [root ledger](../../CHANGELOG.md).

## 0.8.7

Unix `read::hash_file_no_follow(path, max_bytes)` returns the existing
`ArtifactIdentity` through the existing constant-memory hash traversal
([#33](https://github.com/dragginzgame/ic-host-tooling/issues/33)). It shares the
no-follow reader's `NOFOLLOW | NONBLOCK | CLOEXEC` opener and regular-descriptor
admission. Final symlinks preserve their native open error; directories, devices
and an opened FIFO without a writer are rejected before reading. Metadata and
stream size limits are enforced independently, including growth after admission.

The existing `hash_file` retains its following behavior. Trusted ancestors,
concurrent-writer custody, exact expected-length checks, byte budgets and consumer
error classifications remain caller-owned. No whole-file buffer, new digest/error
type or pathname reopening is introduced. Canic's build fingerprints, frontend
capacity and local-fleet hashes can adopt this boundary separately.

The shared snapshot advances to committed Shared Tooling 0.1.33
(`ddd3e1c01ba8aab13a56277e05679e43a8a9d88a`) with 85 selected files.
Host removes its unused fleet tooling reporter
([#32](https://github.com/dragginzgame/ic-host-tooling/issues/32)); run that report
centrally from Shared Tooling. Local `make cloc`, pinned cloc and all tool setup/
offline check commands remain available. An unselected `make cloc-tooling` now
explains the central owner instead of invoking another checkout implicitly.
Common command fixtures cover both omitted and explicitly selected reporters.

The refreshed guidance describes the future Testkit-owned PocketIC handoff;
Host retains its existing IC pin bytes and current six-tool installer contract.
No tool upgrade, installation, schedule or dependency change accompanies this
selection cleanup.

## 0.8.6

`tool::CommunicationLimits` lets `communicate_child` and
`communicate_child_with_observer` accept `timeout: None` for caller-owned builds
or foreground services without an elapsed-time deadline
([#31](https://github.com/dragginzgame/ic-host-tooling/issues/31)). `Some(duration)`
requires a positive, representable deadline. Existing `OutputLimits` arguments
remain accepted with their finite timeout; capture and executable-version
admission continue to require `OutputLimits`.

Both choices use the same fair, bounded I/O engine. Output overflow, cancellation
and callback unwinding retain their cleanup behavior. With no deadline,
communication can wait indefinitely for child exit or pipe EOF; callers retain
cancellation and successful-exit policy, including descendant-held pipes under
`SuccessfulExit::Retain`. Cleanup grace/reap timing is independent and unchanged.
Consumers own output budgets and recovery; this does not introduce a build
scheduler, reader threads or a process supervisor.

## 0.8.4

### Existing lock-file admission

The shared opener admits existing entries directly. It no longer creates and
syncs an empty sibling only to discover the lock file already exists
([#29](https://github.com/dragginzgame/ic-host-tooling/issues/29)). This also lets
a writable regular lock file open under a searchable, non-writable parent.
Missing files still use the existing durable parent/file creation engine once;
competing creators converge on the same admission path. Final-component no-follow,
nonblocking open and descriptor regular-file checks remain authoritative across
path changes. Concurrent removal can return a native not-found error; no unbounded
retry or new locking policy is introduced.

### Shared tooling convergence

The 86-file snapshot now selects committed Shared Tooling
`4e274a2219c0b0cc3af68ec65658b373253518fb`, excluding upstream dirty changes
([#30](https://github.com/dragginzgame/ic-host-tooling/issues/30)). Installers reject
malformed literal active-link targets, including trailing newlines. Consumer
release-runner fixtures simulate Git effects; real-Git tracking qualification
remains with Shared Tooling's separate owner suite.

Host's Cargo release adapter now projects its unchanged phase-specific allowed
metadata paths into `check-release-source.sh`, removing its private inventory
loop. Refusals list staged, unstaged and untracked paths while preserving files
and the index. Initial runner preflight failures explain that validation and
version preparation have not started.

The task catalog and its linked companions are included without activating a
schedule. `ci/ic-tools.tsv` becomes explicitly consumer-owned and retains the
previous bytes, including PocketIC 16.0.0; it is excluded from snapshot refresh
so maintenance does not select an unqualified server upgrade. Package versions,
dependency selections and tool installations are unchanged.

## 0.8.3

`tool::communicate_child_with_observer` adds live output callbacks to the existing
owned-child I/O engine ([#28](https://github.com/dragginzgame/ic-host-tooling/issues/28)).
It reports nonempty retained byte chunks in per-stream order, including the
retained prefix on overflow, without exposing bytes beyond the selected bounds.
Text decoding, event schemas, heartbeat scheduling and limits stay with callers.
The existing cancellation callback remains active while output is silent.
Callback unwinding closes pipes, attempts the owner's selected cleanup and resumes
the original panic even when a caller catches it while retaining the borrowed
owner. Existing communication and capture entrypoints share the same engine.
This provides the mechanism for Testkit's separate observed/unobserved Cargo paths
to converge; consumer adoption and qualification remain separate.

`durable::open_regular_lock_file_with_parents` exposes the existing regular-file
admission owner without acquiring a lock
([#27](https://github.com/dragginzgame/ic-host-tooling/issues/27)). It durably creates
missing parents and the file, preserves existing contents and returns a no-follow,
close-on-exec read/write descriptor. Consumers choose shared or exclusive locking,
descriptor wait callbacks and explicit unlock policy, including clone lifetimes.
Blocking, nonblocking and progress path-lock APIs delegate to this opener and
retain their acquisition behavior. Trusted parents and namespace stability remain
caller responsibilities. No second opener or compatibility alias is introduced.

Lock-admission tests use owned directory, symlink and FIFO fixtures. They no
longer assume `/dev/null` reaches the non-regular-file check: durable creation
first attempts sibling staging, which can fail on `/dev` permissions. Failures
now identify the rejected path and actual error. Production behavior is unchanged.

## 0.8.1

### Nonblocking path locks

`durable::try_lock_regular_file_with_parents` uses the existing regular-file
opener and durable parent/file creation, then attempts the exclusive lock once.
Contention retains `RegularFileLockError::Io` with native `WouldBlock`; existing
bytes and no-follow admission are preserved. The returned close-on-exec descriptor
owns the lock. Blocking and progress APIs keep their contracts. Filesystem latency,
namespace stability, retries and planner policy remain consumer-owned
([#24](https://github.com/dragginzgame/ic-host-tooling/issues/24)).

### Bounded buffer growth

Artifact reads, chunk digest vectors and process capture grow geometrically with
requested capacity capped at the caller's byte/element allowance. Candid
normalization measures the normalized length and reserves once. This avoids an
allocation request per fragment, chunk or line without preallocating the caller's
entire maximum. Existing bytes, identities, limit errors and typed allocation
failures are retained; no public allocator abstraction or dependency is added
([#26](https://github.com/dragginzgame/ic-host-tooling/issues/26)).

### IC report composition

The `inspect_install_limits` example composes bounded source reads, one Wasm
inspection and explicitly selected `REFERENCE_LIMITS`. It distinguishes full
code-section diagnostics from code-body enforcement, defined from imported
functions, and counts all globals. The reference revision accompanies the report.
Caller-selected hard raw-byte admission and soft raw-byte warnings stay separate;
text and JSON share the same previously computed exit decision. The example
requires `ic-limits` and works without the default extraction feature. It is not
a production build CLI or complete Wasm/install validation
([#25](https://github.com/dragginzgame/ic-host-tooling/issues/25)).

### Installer operands and snapshot dependencies

The unchanged 72-file selection now adopts committed Shared Tooling revision
`db039347d2372b877c1c46dcdd2b5c3aa9412009`. Concurrent dirty upstream work is
excluded. Host, IC and Rust installers anchor relative consumer paths before
physical resolution, avoiding inherited `CDPATH` output or redirection and
preserving trailing newlines. The IC installer also anchors its pin-file path
([shared #67](https://github.com/dragginzgame/shared-tooling/issues/67)).

Installer test headers now declare their evidence helper dependencies, so the
canonical exporter refuses incomplete selections before writing consumer files.
The helpers remain explicitly selected; no automatic expansion or duplicated
consumer implementation is introduced
([shared #73](https://github.com/dragginzgame/shared-tooling/issues/73)).
The shared evidence-selector documentation now describes its already-adopted
contract. This snapshot adoption leaves Host CI upload wiring, package versions
and dependency selections unchanged.

## 0.8.0

### Caller-selected termination timing

`OwnedChild::spawn_with_cleanup` accepts `CleanupPolicy::TermThenKill { grace,
reap_timeout }`. Query can select five seconds for each allowance, preserving
its existing timeout/interruption contract
([#5](https://github.com/dragginzgame/ic-host-tooling/issues/5)). The policy lives
on the existing child owner and is used by explicit `terminate`, communication
failure cleanup and Drop, including unwinding. No second IO loop, signal handler,
background reaper or application lifecycle controller is introduced.

Termination signals TERM to the owned group, waits the selected grace after
successful signalling without reaping the leader, then signals group KILL even
if the leader exited during grace. A TERM failure remains visible while KILL
and reaping are still attempted. Group KILL failure retains the existing direct
child kill fallback. Only the leader is reaped; signalling is not descendant-exit
proof or containment of processes that escape the group.

The reap allowance starts after signalling. Reaping uses nonblocking observations,
including after interruption. A zero allowance permits one observation. Repeated
termination and Drop reuse the original allowance without repeating escalation
or starting another wait period. On expiry, `wait_error` has `TimedOut` and the
unreaped child remains owned. The caller may explicitly recover through
`try_wait` or `wait`; dropping instead may leave an unreaped child until parent
exit. There is no hidden blocking destructor or asynchronous recovery service.
Native syscall latency and scheduling are outside these polling bounds.

Communication retains its original timeout/cancellation/IO failure and bounded
output alongside cleanup diagnostics. Its operation deadline excludes the
separate cleanup allowances. Pipes close before failure cleanup, avoiding an
unbounded drain of inherited writers or blocked stdin.

`OwnedChild::spawn` and existing capture entrypoints retain immediate KILL and
synchronous reaping. Explicit natural waits still clean an exited leader's group
without TERM grace. Successful `SuccessfulExit::Retain` still needs explicit
caller admission followed by `handoff`, waiting or termination; starting bounded
termination disallows subsequent communication or background handoff.

Coverage includes a TERM-exited leader with a TERM-ignoring descendant, blocked
input, descendant-held pipes, timeout, cancellation, explicit termination,
unwinding and successful handoff. Reap-expiry coverage substitutes an already
dispatched escalation around a real running child; it does not induce an
unkillable native task. Native and consumer acceptance remain separate in the
[handoff](../status/current.md).

### Breaking cleanup evidence fields

`child::CleanupError` and `tool::ExecutionError` add `term_error: Option<io::Error>`.
`group_error` describes group KILL, `kill_error` the direct-child fallback and
`wait_error` reaping. Update struct literals and exhaustive destructuring; use
`term_error: None` for existing immediate-KILL fixtures. These public struct
changes require the pre-1.0 minor release. No function, method or type is removed.
