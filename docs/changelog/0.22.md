# 0.22 — Exact streams and physical-directory validation

## [0.22.0]

### Breaking

`ArtifactError::LengthMismatch` reports early EOF in exact-length stream reads.
Consumers matching artifact errors exhaustively must handle the new variant.

### Added

Host Artifacts provides exact-length streaming hashes and bounded reads. They
reject premature EOF and probe one excess byte; callers select limits and own
stream custody. See [PR #152](https://github.com/dragginzgame/ic-host-tooling/pull/152).

Native path fixtures follow the host's metadata lookup result when a filesystem
refuses non-UTF-8 directory creation: missing paths remain admitted, and other
lookup errors remain intact. Creation and lookup need not return the same error.
Positive Unicode, relative-path and missing-component controls remain covered.
Production pathname admission is unchanged.

`ic-host-fs::path::validate_physical_directory_allow_missing` checks existing
components without creating directories. Symlinks (including dangling links),
non-directories and `..` reject; missing components are permitted. Private-parent
preparation reuses this validator before its durable creation phase. No path
is canonicalized or selected implicitly, and native names remain unchanged.

Callers retain pathname-content and absolute-path policy, namespace exclusion,
and all later creation/locking/publication decisions. This point-in-time check
is not confinement or a held directory capability. Testkit can use it for
read-only PocketIC bundle checks as well as explicit setup; normal consumer
adoption requires a published Host release containing this API.
