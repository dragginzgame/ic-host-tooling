# 0.22 — Explicit publication, raw extraction and retired adapters

## [0.22.0]

### Breaking

#### Byte publication options

`durable::write_bytes(path, options, bytes)` now takes the same `WriteOptions`
as streaming and named publication. The create-only byte wrappers are removed;
there are no compatibility aliases. To preserve previous behavior, select:

| Previous call | `WriteOptions` |
| --- | --- |
| `write_bytes(path, bytes)` | `mode: PublicationMode::Replace, permissions: 0o666` |
| `create_new_bytes_with_parents(path, bytes)` | `mode: PublicationMode::CreateNew, permissions: 0o666` |
| `create_private_bytes_with_parents(path, bytes)` | `mode: PublicationMode::CreateNew, permissions: 0o600` |

Unix permissions remain subject to umask. Create-only publication still refuses
occupied destinations. Parent creation, publication phases, original I/O causes
and separate cleanup evidence continue through the single durable engine.
Consumers retain stronger selected permissions and all recovery policy.

#### Raw Candid extraction

`ExtractedCandid.text` and `ExtractionError::Normalize` are removed. Extraction
returns source/tool identities and complete bounded raw process evidence, retaining
source-change, execution and output-limit rejection. Successful non-UTF-8 or empty
stdout is raw evidence; extraction alone does not admit it as a Candid service.

Consumers needing normalized text call
`candid::text::normalize(&extracted.evidence.stdout, max_bytes)` explicitly and
handle its typed error at their own text-admission boundary. A final newline may
need one additional byte beyond the captured stdout allowance. The example now
performs this composition. Callers already consuming raw stdout need no duplicate
normalization or retained text allocation. Grammar and service policy remain
consumer-owned.

#### Tar-member retirement

The Artifacts `archive` feature, `archive::extract_tar_gz` and its associated
types are removed, along with the optional `tar` dependency, tar-only fixtures
and the filesystem `inspect_archive` example. No maintained sibling calls the
tar-member API. Testkit selects the removed feature for gzip use; it must select
`gzip` instead, preserving any separately selected `wasm` feature.

Gzip encoding, decoding, identities and bounded comparisons remain supported.
Unknown external tar consumers must select an archive owner explicitly before
upgrading and preserve their path, member-kind, duplicate, digest and byte-limit
admission; there is no unrestricted unpack fallback. This retirement changes
source/feature selection only and removes no retained consumer artifacts.

#### Consumer coordination

These are registry-adoption requirements after publication, not completed
consumer qualification. Existing selected graphs and sibling sources are retained.

| Consumer | Owning migration |
| --- | --- |
| Canic | [#458 — Adopt published IC Host Tooling](https://github.com/dragginzgame/canic/issues/458): preserve replace/create-only/private choices across journals, seeds and diagnostics |
| IC Build | [#9 — Qualify consumers against the current exposed Host boundary](https://github.com/dragginzgame/ic-build/issues/9): explicit options for cache and transaction byte writes |
| IC Testkit | [#107 — Adopt Host 0.22 explicit byte options and replace retired archive feature](https://github.com/dragginzgame/ic-testkit/issues/107): retained diagnostics and `gzip` feature selection |
| IcyDB | [#307 — Adopt split host owners](https://github.com/dragginzgame/icydb/issues/307): sidecar/report writes; keep exact raw extractor text |
| IC Query | [#68 — Adopt Host 0.22 explicit byte options in Governance smoke](https://github.com/dragginzgame/ic-query/issues/68): probe artifact/output writes |
| IC Memory | [#92 — Adopt published Host verified copying](https://github.com/dragginzgame/ic-memory/issues/92): contributor receipt/metadata byte writes |
| IC Crates | [#6 — Adopt Host 0.22 explicit create-only private publication](https://github.com/dragginzgame/ic-crates/issues/6): publisher's private create-only write |
| IC Blob Storage | [#69 — Adopt published Host custody/output APIs](https://github.com/dragginzgame/ic-blob-storage/issues/69): create-only storage-resource fixture setup |

#### Response formats

`ResponseFormat::LabeledHex` and `ResponseError::MissingHexLabel` are removed.
`response::decode` accepts explicitly selected JSON or plain hex, with unchanged
input/decoded-byte limits, fallible decoded allocation, JSON envelope checks and
ASCII whitespace admission for plain hex. Neither mode infers a presentation
label or discards a preamble. The `inspect_response` example accepts `json|hex`.

Consumers using the removed variant must select a supported output format or
admit and normalize their CLI presentation before passing the resulting body to
the codec. IcyDB already owns its label/preamble and Unicode whitespace policy;
that policy is broader than the removed strict label adapter and is not moved
into Host. Canic continues selecting JSON. No sibling source or retained data is
changed by this cut, and no compatibility alias or fallback is provided.

### Changed

#### Existing-parent publication

`durable::write_existing_parent_with(path, options, produce)` and
`write_existing_parent_validated_with(path, options, produce, admit)` select an
existing parent once and reuse descriptor-relative durable publication. Missing
parents are refused without creation. Invalid names/permissions and non-directory
parents refuse before staging or callbacks; directory-only opening rejects a FIFO
without waiting for a writer. Parent symlinks remain supported. A held directory
stays selected across pathname rename, and final symlinks follow the existing
Replace/CreateNew entry policy rather than being followed for writes.

The validated variant admits the producer's result after file synchronization and
before publication. Original producer/admission errors, separate cleanup evidence
and before/after-publication failures retain their existing typed contracts.
Callers own namespace custody, permissions, budgets, cancellation and recovery.
There is no new publication engine, policy type, dependency or compatibility path.
This adapts [PR #150 — Existing-parent publication](https://github.com/dragginzgame/ic-host-tooling/pull/150)
for [#148 — Existing-parent pathname publication](https://github.com/dragginzgame/ic-host-tooling/issues/148),
including a non-directory-parent regression beyond the original PR.
IcyDB diagnostic output and Testkit fixture reuse can retire their pathname
preparation after published registry adoption and their own qualification.

Descriptor streaming with and without result admission now shares one adapter,
including supported-platform dispatch. Public entrypoints, producer results,
permissions, publication phases and cleanup evidence retain their contracts.

#### Explicit process diagnostics

`ic_host_process::tool::format_failure_evidence(context, &error)` projects the
caller-selected context, observed status, lossy UTF-8 stdout/stderr with trailing
whitespace trimmed, and independent cleanup failures. Ordinary `ToolError`
Display/Debug keep omitting captured bytes. This is explicitly requested raw
diagnostic text; callers retain terminal escaping, redaction and output policy.
The helper borrows the error and changes no admission, capture limits, child
execution or retry behavior.

This adapts [PR #151 — Opt-in process failure diagnostics](https://github.com/dragginzgame/ic-host-tooling/pull/151)
for [#149 — Explicit process failure-evidence rendering](https://github.com/dragginzgame/ic-host-tooling/issues/149).
IcyDB can remove its generic formatter from the Wasm optimizer owner after
published adoption, as tracked by
[#307 — Adopt split host owners](https://github.com/dragginzgame/icydb/issues/307).
Sibling source and dependency selections remain unchanged in this batch.

#### Contributor tooling and text clipping

Routine Host validation no longer replays Shared Tooling's generic formatter
prerequisite, hook, synthetic Make-consumer and tool-command regression suites.
Those implementation matrices remain with Shared Tooling. Host retains the actual
Cargo manifest/Rust formatter/hook adoption check, selected-file preservation,
Make routing, aggregate/preflight failure ordering, LOC arguments/status and
pipe-jobserver checks, prepared-tool admission and required native CI. Common
Make fixture setup and per-target unsafe-mode probes now use Shared helpers;
exhaustive flag aliases and inherited/replaced combinations remain upstream.
Native CI uses the shared tool-preparation action, retaining install/check logs
and publishing PATH only after both succeed. Compiler selection, cache identity
and early host preparation for that identity remain local. The obsolete
`format-tools-test` Make target is retired; use `fmt-check` and
`formatting-hook-check` for Host qualification. `tooling-command-check` still runs
the Host-specific fixtures and release-command admission.

The canonical snapshot selection retires those generic fixture roots and their
unused frontend formatter and generic jobserver-probe companions. The local
Host routing fixture still checks real pipe descriptors through its Cargo
substitute. Fixture retirement changes selection only; it requires no tool
installation or application rebuild.

Shared Tooling advances to 0.15.6 at committed revision
`5910c9fe95429aa5741589f7e6d0cec9b6c84384`. The exporter reuses admitted committed
payloads, preserves failed Git mode observations and avoids repeated external
path utilities while retaining source, consumer and index drift checks.
Maintenance runtime selection remains optional; Host preserves its existing
operational selection without activating a scheduler. Three new helper/action
roots bring the snapshot to 88 entrypoints and 108 payloads. Common executable
pins, Host's Rust toolchains, package versions and MIT notices remain unchanged.
The optional Rust panic scanner is not selected by this adoption; it adds no
dependency, validation gate or Rust build requirement to Host.

`ic-host-text::width::fit_line` now consumes the same private escape iterator as
`escape::terminal_text`, clipping without constructing a complete escaped copy
or scanning the whole escaped line first. It retains the exact-fit decision,
Unicode scalar widths, zero-width characters, visible control escapes and existing
ellipsis placement. `terminal_text` continues borrowing safe input. There is no
public API, formatting-contract or dependency change; callers still own input
byte limits, and zero-width input is not bounded by a column allowance.

# 0.22 — Root-relative no-follow reads

## [0.22.0]

### Added

Unix root-relative no-follow opening admits regular files and directories
through retained parent descriptors. Traversal, symlinks and unsupported entries
refuse; unsupported entries report their observed file kind. Callers own root
custody, content validation, byte budgets and concurrent writer exclusion.
Directory renames preserve the selected descriptor but do not prove current
pathname containment. This covers the read subset of
[#80 — Capability-rooted filesystem confinement](https://github.com/dragginzgame/ic-host-tooling/issues/80); create/remove/scan work remains separate.
