# 0.31 migration

## 0.31.2

Native CI again runs FS core, capability-only and temporary-file-only tests
independently, alongside the existing all-feature and dependency graph checks.
Published behavior and feature names are unchanged. Historical 0.28.1 preparation
guidance now explicitly identifies 0.29.0 as the supplying extraction release
([#209 — Release notes advertise absent scoped temporary files](https://github.com/dragginzgame/ic-host-tooling/issues/209)).

## 0.31.1

### Platform 0.4 adoption

Host selects `ic-platform = "0.4"` with defaults disabled. Platform's breaking
runtime-call, reject-code and signature-helper changes affect features Host does
not enable. Host's Registry helpers retain Platform-owned principals, and external
Agent/Candid DTOs retain their existing identities and explicit conversions.
No Host API migration is required for this update.

Default Host profiles remain Platform-free; certificate-only and interface-only
profiles remain Candid/parser-free. The Rust 1.88 floor, optional features,
certificate admission and aggregate reply-decoding contracts are unchanged.

## 0.31.0

### Platform 0.3: owned Principal boundary

Host selects `ic-platform = "0.3"` with defaults disabled. Platform now owns its
root `Principal` identity, retaining external principal types for required SDK
and Candid interfaces. Host's Registry shard helpers take and return that owned
type. Update type annotations and convert external principals explicitly:

```rust
let owned = ic_platform::Principal::from(external);
let external = ic_platform::principal::ExternalPrincipal::from(owned);
```

These conversions preserve significant identity bytes. Registry key admission,
interval checks and Protobuf tags are unchanged. Agent construction still returns
the original SDK builder/agent; its calls require the external principal. Required
Candid DTOs continue using `ic_platform::candid::contract::Principal`, the same
external identity, rather than the owned root type. No Candid trait is added to
the owned type. Platform also adds owned Account/Subaccount types, but Host's
external ledger evidence continues using the existing ledger DTOs.

Default Host graphs remain Platform-free. Certificate-only and interface-only
profiles remain Candid/parser-free; Registry remains codec/runtime-free. No CDK
or executor feature is selected, and the Rust 1.88 floor is unchanged.

### Shared Tooling 0.25.3

Selected Cargo-tool setup and offline admission now accept repeatable `--features`
arguments. Feature-gated binaries such as `ic-host-file` require `--features cli`
on both setup and check. Requested names normalize to one set, selecting a separate
immutable installation and matching Cargo's receipt. Package defaults remain
enabled; `--all-features` and `--no-default-features` are not supported. Host's
common formatters and release editor retain their featureless selections.

Shared's Cargo-tool checks now identify the rejected selection, receipt or source
and print a setup command retaining the consumer's arguments. Tool pins, compiler
selection and library dependency requirements are unchanged. The build-helper
fingerprint changed: run `make install-tools` once to prepare the selected tools
under that identity; offline checks refuse older selections without repairing them.
Previous tool generations remain retained.

The baseline also clarifies Wire ownership for application endpoints and imported
runtime/crypto maintenance. Host owns no canister endpoints or runtime; its optional
Candid and certificate helpers continue interpreting independently specified IC
protocols through Platform. This adoption requires no public Host API removal.

### One optional YAML boundary aligned with ICP CLI

`ic-host-text` owns single-document UTF-8 YAML decoding through its opt-in `yaml`
feature. Its private dependency is `serde_yaml = "0.9.34"`, matching
[ICP CLI's reviewed manifest](https://github.com/dfinity/icp-cli/blob/0ea5fc5f0198b01f0d8491182647e62503adf6a5/Cargo.toml).
Default Text and Tools graphs remain YAML-free. Rust 1.88 is retained throughout;
there is no second compiler floor or feature-specific MSRV lane.

The API is `ic_host_text::yaml::from_slice::<T>(bytes, maximum_input_bytes, policy)`.
Consumers supply an owned Serde schema and `DecodePolicy`:

- Input bytes are admitted before UTF-8 decoding or parsing. The backend's
  recursion/repetition checks remain; Host does not expose configurable depth,
  event, scalar or alias budgets, or promise a memory/CPU ceiling from byte admission.
- A private YAML value tree rejects duplicate mapping keys before typed projection,
  including content ignored by the schema. Scalars retain their YAML types;
  numeric values are not coerced into strings during projection.
- Default policy rejects non-core tags and every `<<` key, including quoted keys.
  Callers may accept tagged values or preserve `<<` as an ordinary key. Merge
  expansion, filesystem includes and environment/property interpolation never run.
- Errors use Host-owned categories; parser diagnostics may contain input values
  and their wording is not stable. Consumers own redaction and public error mapping.

Host owns parser selection and generic admission. Consumers retain schemas,
configuration discovery, persistence, file access and domain policy. Aligning
with ICP CLI deliberately retains its unsafe-libyaml backend and the known
[upstream maintenance limitation](https://rustsec.org/advisories/RUSTSEC-2024-0449.html).
This is package/configuration alignment, not a new IC wire format or a claim that
all IC packages use YAML or one parser.

### ICP projection migration

`icp_project::environment_network` retains its original byte-limit argument,
effective-configuration projection, exact identity checks and refusal of duplicate
or empty identities. The payload of `ProjectParseError::InvalidYaml` changes from the
upstream serde_yaml_ng error to `ic_host_text::yaml::DecodeError`. Update code
that matches or annotates that payload; callers do not need another dependency
merely to continue invoking the projection with a byte allowance.

ICP tags in ignored fields remain accepted, and merge keys remain ordinary keys.
Duplicate keys in ignored content are now rejected. Raw manifest resolution still
belongs to ICP; this adapter does not discover or expand configuration.

Canic's manifest adapter is a verified prospective consumer but remains unchanged.
Its existing whole-document duplicate/tag/merge checks can delegate to the shared
YAML decoder with default policy, including its quoted-`<<` rule, before decoding
its own optional raw-manifest schema. Preserve its null/empty behavior and public
errors. Host's effective-project projection does not replace that schema or its
application rules. Sibling adoption follows publication and focused consumer checks.
