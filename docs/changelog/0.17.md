# 0.17 — Independent Wasm and Candid inspection

## [0.17.8]

`OwnedChild::from_spawned_direct` takes an existing `std::process::Child` without
respawning or granting process-group ownership. Custody-aware callers can use
Host's bounded communication, cancellation and direct-child kill/wait cleanup
after their own authorized spawn. The caller transfers reaping responsibility;
the existing executable-admission and ordinary spawn paths remain unchanged.
The direct-child regression covers retained IO, successful reaping and cancellation.

Adopt Shared Tooling 0.12.0 at `f7fe31bf80a2b445bf37a470527f001210241aea`.
The canonical release-note finalizer requires a numbered top candidate and
rejects unnumbered, misplaced, competing or finalized entries. Host removes its
equivalent guards while retaining source-bound receipts, exact payload checks
and interruption recovery. Cargo tool cache keys reuse the snapshot's literal
catalog reader, and IC fixtures report cleanup timing and failures.
The optional publication runner remains outside Host's selected implementation;
its existing package/provenance admission and upload recovery policy stay local.
Tool pins and library APIs are unchanged; no consumer migration is required
([#73](https://github.com/dragginzgame/ic-host-tooling/issues/73),
[#75](https://github.com/dragginzgame/ic-host-tooling/issues/75)).

Retained staging uses the durable engine's existing checked permission conversion.
Darwin's narrower native mode is admitted without changing the public `u32`
argument, exclusive creation, directory synchronization or retained failure
custody. Invalid permission bits, including high bits that would be lost by
narrowing, refuse before creating a stage. No consumer migration is required
([#84](https://github.com/dragginzgame/ic-host-tooling/issues/84)).

Trusted process and extraction fixtures use observed-version admission directly,
removing their preliminary hash followed by a second admission hash. Shared
version behavior has one focused coverage owner; ordinary digest-pinned admission
still checks rejection before dispatch, matching identity/version and mismatched
version evidence. Production admission and public APIs are unchanged
([#85](https://github.com/dragginzgame/ic-host-tooling/issues/85)).

Git observations use one ordered query loop and failure-evidence projection.

later queries still stop at the first failure. Add malformed-tree and failed-status

tools feature profiles and the Wasm CLI. Each pipe-jobserver probe must execute
its substitute; unsafe Make modes must stop before any substituted effect.
The publication guide now describes four libraries plus the CLI, both source
layouts, all selected licenses and dependency-respecting partial-upload recovery.
Public APIs and publication policy are unchanged
([#83](https://github.com/dragginzgame/ic-host-tooling/issues/83)).

### Testkit host mechanics

`AdmittedTool::admit_no_follow` performs one bounded identity check before version
execution and rejects final-component links on subsequent runs. Ordinary
alias-following and observed-version admission keep their contracts.

`ic_host_process::sampling` owns the existing Linux /proc and macOS ps observations
and checked descendant RSS summation. Consumers select the Linux record budget,
workload root, sampling cadence and report meaning; source identities, RSS units
and process-disappearance handling are preserved. No sampling deadline is added.

`write_at_validated_with` checks the producer result after file sync, before
publication beneath a borrowed admitted directory. It creates
no parent and retains typed producer, cleanup and publication-phase errors.
These additive APIs permit Testkit cleanup without changing cache formats
([#79](https://github.com/dragginzgame/ic-host-tooling/issues/79)).

Release preparation and committed recovery use one expected-payload comparator.
Working-tree admission and locked Cargo validation remain in preparation;
recovery still materializes the selected commit and ignores newer working files.
Receipt, exact metadata projection and changelog checks remain intact
([#75](https://github.com/dragginzgame/ic-host-tooling/issues/75)).

## [0.17.0]

### Breaking

`ic-host-tools`'s `ic-interface` feature now enables Wasm export interpretation
without `candid_parser`. Consumers using `candid::service` must select the new
`candid-service` feature, which also enables `ic-interface`:

```toml
# Workspace root
[workspace.dependencies]
ic-host-tools = "0.17"

# Consuming package
[dependencies]
ic-host-tools = { workspace = true, features = ["candid-service"] }
```

Keep `ic-interface` for Wasm-only consumers. Keep `candid-extraction` explicitly
selected wherever native extraction is needed. Defaults remain empty; service
inspection does not enable filesystem or process dependencies. API paths and
service inspection behavior remain unchanged. This reduces host dependency
selection; it does not change a canister's Candid exports or claim a deployed
Wasm-size reduction.

### Internal cleanup

Bounded copying uses the existing hashing writer to identify accepted bytes.
Source limits, typed input/output errors, partial-output preservation and
caller-owned publication remain unchanged; copying never flushes the sink.

Durable filesystem tests share the existing owned fixture instead of generating
timestamp paths and repeating cleanup. Missing-parent cases still begin with
absent directories. Successful fixtures clean up automatically; a fixture dropped
during a panic is retained with its path printed for diagnosis.

Dependency-graph checks and separate Wasm/service test profiles protect the
feature boundary ([#72](https://github.com/dragginzgame/ic-host-tooling/issues/72)).
