### Testkit host mechanics

`AdmittedTool::admit_no_follow` performs one bounded identity check before version
execution and rejects final-component links on subsequent runs. Ordinary
alias-following and observed-version admission keep their contracts.

`ic_host_process::sampling` owns the existing Linux /proc and macOS ps observations
and checked descendant RSS summation. Consumers select the Linux record budget,
workload root, sampling cadence and report meaning; source identities, RSS units
and process-disappearance handling are preserved. No sampling deadline is added.

`write_at_validated_with` checks the producer result after file sync, before
publication beneath a borrowed admitted directory. It creates
no parent and retains typed producer, cleanup and publication-phase errors.
These additive APIs permit Testkit cleanup without changing cache formats
([#79](https://github.com/dragginzgame/ic-host-tooling/issues/79)).

Release preparation and committed recovery use one expected-payload comparator.
Working-tree admission and locked Cargo validation remain in preparation;
recovery still materializes the selected commit and ignores newer working files.
Receipt, exact metadata projection and changelog checks remain intact
([#75](https://github.com/dragginzgame/ic-host-tooling/issues/75)).

## [0.17.1]

### Testing

Filesystem, process and tools fixtures skip occupied directory names instead of
failing when a retained fixture survives PID reuse. Existing files, directories
and symlinks are never reused or deleted to acquire a name; other creation errors
still fail. Process and tools fixtures now retain their roots during panic
unwinding and print the evidence path, matching filesystem fixtures. Successful
fixtures still clean up, and process serialization remains local to each crate.

Native CI independently tests the `candid-extraction` and `ic-limits` profiles
with defaults disabled, alongside the existing response, Wasm and service
profiles. These checks reuse existing tests and protect against dependencies
accidentally supplied by another feature. Library APIs and behavior are unchanged
([#72](https://github.com/dragginzgame/ic-host-tooling/issues/72)).

### Contributor tooling

IC catalogs used by setup, formatting and failure-evidence checks. Host's existing

Adoption runs explicit setup and offline admission while retaining existing
shared bundles and failure evidence. No library API or dependency changes are
required by this contributor-tooling migration.

Retain 0.9.16's fixes: LOC reports reject literal and resolved directory
paths containing CR/LF before they can select a different checkout or print

Release lock acquisition preserves the filesystem diagnostic and exit status,
distinguishes occupancy from other failures and leaves existing state intact
([Shared #152](https://github.com/dragginzgame/shared-tooling/issues/152)).

resolved directory paths containing CR/LF before probing the CLI or writing

The adopted guidance also describes recovery of failed-job logs from the
selected CI attempt when failed-step logs are empty; Host does not select the

unchanged. Library consumers need no migration.

## [0.17.0]

### Breaking

`ic-host-tools`'s `ic-interface` feature now enables Wasm export interpretation
without `candid_parser`. Consumers using `candid::service` must select the new
`candid-service` feature, which also enables `ic-interface`:

```toml
# Workspace root
[workspace.dependencies]
ic-host-tools = "0.17"

# Consuming package
[dependencies]
ic-host-tools = { workspace = true, features = ["candid-service"] }
```

Keep `ic-interface` for Wasm-only consumers. Keep `candid-extraction` explicitly
selected wherever native extraction is needed. Defaults remain empty; service
inspection does not enable filesystem or process dependencies. API paths and
service inspection behavior remain unchanged. This reduces host dependency
selection; it does not change a canister's Candid exports or claim a deployed
Wasm-size reduction.

### Internal cleanup

Bounded copying uses the existing hashing writer to identify accepted bytes.
Source limits, typed input/output errors, partial-output preservation and
caller-owned publication remain unchanged; copying never flushes the sink.

Durable filesystem tests share the existing owned fixture instead of generating
timestamp paths and repeating cleanup. Missing-parent cases still begin with
absent directories. Successful fixtures clean up automatically; a fixture dropped
during a panic is retained with its path printed for diagnosis.

Dependency-graph checks and separate Wasm/service test profiles protect the
feature boundary ([#72](https://github.com/dragginzgame/ic-host-tooling/issues/72)).
