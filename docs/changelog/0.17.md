# 0.17 — Independent Wasm and Candid inspection

## [0.17.0]

### Breaking

`ic-host-tools`'s `ic-interface` feature now enables Wasm export interpretation
without `candid_parser`. Consumers using `candid::service` must select the new
`candid-service` feature, which also enables `ic-interface`:

```toml
# Workspace root
[workspace.dependencies]
ic-host-tools = "0.17"

# Consuming package
[dependencies]
ic-host-tools = { workspace = true, features = ["candid-service"] }
```

Keep `ic-interface` for Wasm-only consumers. Keep `candid-extraction` explicitly
selected wherever native extraction is needed. Defaults remain empty; service
inspection does not enable filesystem or process dependencies. API paths and
service inspection behavior remain unchanged. This reduces host dependency
selection; it does not change a canister's Candid exports or claim a deployed
Wasm-size reduction.

### Internal cleanup

Bounded copying uses the existing hashing writer to identify accepted bytes.
Source limits, typed input/output errors, partial-output preservation and
caller-owned publication remain unchanged; copying never flushes the sink.

Durable filesystem tests share the existing owned fixture instead of generating
timestamp paths and repeating cleanup. Missing-parent cases still begin with
absent directories. Successful fixtures clean up automatically; a fixture dropped
during a panic is retained with its path printed for diagnosis.

Dependency-graph checks and separate Wasm/service test profiles protect the
feature boundary ([#72](https://github.com/dragginzgame/ic-host-tooling/issues/72)).
