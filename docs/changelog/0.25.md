# 0.25 migration

## [0.25.2]

Share explicit Unix signal-action installation, reverse-order restoration and
partial-install rollback through `ic_host_process::signal::SignalActions`.
Callers retain exclusive process-global registration custody, signal sets,
static async-signal-safe callbacks and shutdown policy. Installation is unsafe
to make those caller obligations explicit. Typed installation errors retain the
original cause separately from rollback failure; explicit restoration reports
errors and Drop makes a best-effort restoration attempt. No handlers are installed
implicitly by other Host APIs
([#107 — Scoped Unix signal-action installation and restoration](https://github.com/dragginzgame/ic-host-tooling/issues/107)).

## One version-probe configuration

Use `ic_host_process::tool::VersionSpec` for both observation and verification.
It contains only `executable`, `executable_bytes` and `version_arguments`.
The separate `VersionObservationSpec` and the `version_identity` field retire
without aliases. Supply the exact expected version to verifying entrypoints:

```text
AdmittedTool::admit(&spec, expected_digest, expected_version, &context, limits)
AdmittedTool::admit_no_follow(&spec, expected_digest, expected_version, &context, limits)
AdmittedTool::admit_version(&spec, expected_version, &context, limits)
AdmittedTool::observe_version(&spec, &context, limits)
```

Observation remains provenance for a caller-trusted installation. Exact-version
admission still requires a nonempty, already-trimmed expected version; pinned
admission additionally authenticates the digest before executing the probe.
No-follow admission, complete successful UTF-8 output, output budgets, optional
deadlines and later byte-drift checks retain their existing behavior.

## Consumer-owned replica install policy

Host Tools no longer exposes `install_limits`, the `ic-limits` Cargo feature or
`inspect_install_limits`. Remove that feature from dependency declarations.
Keep `ic_host_artifacts::wasm::inspect` for generic structural facts; choose and
compare replica thresholds in the consumer that owns its deployment target.

Canic's policy belongs beside enforcement in
`crates/canic-host/src/artifact_io/wasm/limits/`. Its migration preserves the
selected replica source revision, inclusive limits, warning headroom and error
ordering. Code-body bytes exclude the encoded function-count prefix; function
counts exclude imports; global counts include imports. These comparisons alone
do not prove installability on a deployed subnet. Apply and qualify that consumer
migration before selecting this Host release. Other consumers of the retired
example must retain their own output schema and exit policy.

## Candid interpretation stays in Host Tools

Host Tools owns shared Candid parsing, service inventories and IC method identities.
IC Build retains extractor execution and captured artifact evidence. Product
bindings, expected interfaces and deployment acceptance remain consumer policy.

`candid_parser` is a normal Host Tools dependency, so `candid::service` and method
identities are available without feature selection. Remove `candid-service` from
consumer feature lists; the feature is retired without an alias. Keep
`ic-interface` when Wasm export projection is needed. Parser/type-checking and
source/method bounds are unchanged. Disabling default features no longer excludes
Candid. The other four Host libraries and the standalone Wasm inspector retain
their graphs without Candid parsing.

`make test-tools-default` replaces the response-only and service-profile targets;
it checks the default service/response API and example compilation together.

## Explicit durable result admission

`write_at_with` and `write_existing_parent_with` retire without aliases. Use
`write_at_validated_with(parent, name, options, produce, admit)` or
`write_existing_parent_validated_with(path, options, produce, admit)`.

The admission callback runs after successful production and file synchronization,
before publication. Preserve existing validation when present. Otherwise use
`|_| Ok(())`, or `|()| Ok(())` for a unit result. Publication modes, permissions,
parent/descriptor selection, typed producer errors and separate cleanup failures
are unchanged. An already-published error still requires consumer reconciliation.
Query and Blob retain their existing create/replace choices and error projection.

## Shared test-directory custody

With the FS `test-support` feature, `testing::FixtureDirectory::new(parent, prefix)`
allocates a fresh directory and owns cleanup. Normal Drop attempts removal;
unwinding retains evidence and prints its path. Borrow its path through
`path()`. The bare `create_fixture_directory` allocator retains its existing
explicit-retention contract. Production `OwnedDirectory` still attempts cleanup
during unwind; its semantics are unchanged.

Canic's duplicate acknowledged crash barriers can use Host Process's existing
`testing::crash_barrier` functions directly with its current five-second Backup
and thirty-second CLI allowances. Error-returning calls retain local test failure
reporting. Child readiness/acknowledgement markers and persistence assertions
remain unchanged; no live ICP environment is selected by this migration.
