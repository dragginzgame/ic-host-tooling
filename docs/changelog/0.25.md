# 0.25 — Explicit publication admission and shared host primitives

## [0.25.0]

### Fixed

The staged HTTP line/header fixture accepts on the blocking listener, then makes
the connected stream nonblocking. This removes the setup race observed by
PR #172's macOS Intel job while exercising the intended nonblocking reader and
preserving the channel-controlled header release. Production I/O is unchanged.

### Breaking

Replace `write_existing_parent_with` and `write_at_with` with
`write_existing_parent_validated_with` and `write_at_validated_with`. Supply an
explicit result-admission callback: `|_| Ok(())` when production already admits
the result, or `|()| Ok(())` for unit results. File sync still precedes admission;
held-directory custody and typed producer, cleanup and publication-state evidence
are retained. Closed-writer pathname admission keeps its executable-probe duties.
Query, Blob CLI and IcyDB update these calls during published-package adoption
([#168](https://github.com/dragginzgame/ic-host-tooling/issues/168)).

### Added

With `gzip` enabled, `artifact::copy_gzip` decodes one bounded member directly
into a caller-owned writer and returns its decoded identity. It reuses the
existing copy and framing engines, rejecting CRC, length, budget and trailing
member failures. Errors may leave partial or complete decoded bytes in the sink;
authenticate input first and publish private staging only after success and
caller admission. Native sink causes remain in `GzipError::Decode(ArtifactError::Io)`;
the helper never opens, flushes, syncs or publishes files
([PR #171](https://github.com/dragginzgame/ic-host-tooling/pull/171)).

`durable::copy_verified` streams a regular source through the durable writer and
checks its digest before publication. Digest/limit/input rejection preserves the
prior destination; after-publication failures retain their typed state. Source
paths follow symlinks; Unix special files refuse without waiting for FIFO writers.
Callers retain source custody, limits, reuse and retained-file verification
([PR #104](https://github.com/dragginzgame/ic-host-tooling/pull/104)).

Unix `copy::{copy_file, copy_directory}` copies held descriptors into create-new
private output. Tree copies preserve empty directories and return file identities,
rejecting symlinks, special entries and non-UTF-8 names. Partial output remains
caller-owned; aggregate limits, digest framing, file sync, publication and cleanup
remain with consumers. These operations do not claim durable file publication
([PR #165](https://github.com/dragginzgame/ic-host-tooling/pull/165)).

Unix `durable::write_retained_at_with` performs exclusive named production and
file/directory sync. Producer errors and panics retain the named partial entry.
`RetainedWriteError` distinguishes creation, production and synchronization
phases. Directory/name/permission custody and recovery remain caller policy;
an error authorizes neither deletion nor automatic retry
([PR #132](https://github.com/dragginzgame/ic-host-tooling/pull/132)).

`framing::read_line` and `framing::LineFramer` require byte allowances including
LF. Refused prefixes retain at most one excess byte; chunk framing reuses scratch
and rejects later input after failure. Callers own schemas, unterminated-tail
acceptance, diagnostics, deadlines and process lifetime
([PR #128](https://github.com/dragginzgame/ic-host-tooling/pull/128)).

`status::shell_status_code` preserves exit codes, maps Unix signals to
`128 + signal`, and leaves unclassified status as `None`. Callers retain fallback
and exit-code range policy; the helper performs no process operation
([PR #133](https://github.com/dragginzgame/ic-host-tooling/pull/133)).

The inspector guide documents direct managed installation, offline checking and
invocation with consumer-selected versions and limits. Its CLI is unchanged
([PR #156](https://github.com/dragginzgame/ic-host-tooling/pull/156)).
