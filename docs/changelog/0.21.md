# 0.21 — Independent Candid and Wasm inspection

## [0.21.1]

Native path fixtures compare filesystem refusals with the host's own metadata
errors and retain positive Unicode, relative-path and missing-component controls.
They no longer require arbitrary non-UTF-8 directory creation on filesystems
that reject it. Production pathname admission is unchanged.

`ic-host-fs::path::validate_physical_directory_allow_missing` checks existing
components without creating directories. Symlinks (including dangling links),
non-directories and `..` reject; missing components are permitted. Private-parent
preparation reuses this validator before its durable creation phase. No path
is canonicalized or selected implicitly, and native names remain unchanged.

Callers retain pathname-content and absolute-path policy, namespace exclusion,
and all later creation/locking/publication decisions. This point-in-time check
is not confinement or a held directory capability. Testkit can use it for
read-only PocketIC bundle checks as well as explicit setup; normal consumer
adoption requires a published Host release containing this API.

## [0.21.0]

### Breaking

`ic-host-tools`'s `candid-service` feature no longer enables `ic-interface`.
Candid service inspection and its shared `interface::{MethodMode, ExportedMethod}`
types remain available without Host Artifacts or the Wasm parser. Consumers using
`interface::exported_methods` must select `ic-interface` explicitly, alongside
`candid-service` when comparing declared services and Wasm exports. Public type
paths and service inspection results are unchanged. Consumers already selecting
both features require no source change. No retained-data migration is needed.

### Changed

Durable publication uses explicit writable/read-only custody for its admission
phase. Ordinary writers use the same admission path without a separate optional
callback mode. The producer and unused admission callback remain alive through
failure cleanup; closed-writer validation, value-only admission, synchronization,
inode checks and before/after-publication errors retain their existing contracts.

Optional no-follow opening retains the initial missing-file and pathname-type
checks, then passes the selected descriptor to its reader. Bounded and private
readers each perform their complete descriptor admission once. Private admission
checks regular-file type before length, permissions or link count, preserving
typed special-file rejection even if selection changes after the pathname check.
Symlink, FIFO, concurrent-removal and source-growth contracts remain unchanged;
no byte limits, source mutation, retry or regeneration policy is added.

### Fixed

`GitObservations::is_dirty()` reflects retained status stdout rather than the
publicly editable report identity's byte count. Editing cached metadata cannot
turn a dirty observation clean, or a clean observation dirty. Capture admission,
status scope, raw evidence and the public report fields remain unchanged.
