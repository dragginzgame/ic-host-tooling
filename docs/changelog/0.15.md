# 0.15 release notes

## [0.15.0]

Qualification and consumer adoption:
[#71](https://github.com/dragginzgame/ic-host-tooling/issues/71).

### Breaking: separate Candid text and extractor APIs

The combined `ic_host_tools::candid` surface is split by responsibility. Update
imports directly; the previous paths have no compatibility reexports:

| Previous path under `ic_host_tools::candid` | Current path |
| --- | --- |
| `normalize`, `NormalizationError` | `candid::text::{normalize, NormalizationError}` |
| `extract`, `ExtractionError`, `ExtractedCandid` | `candid::extraction::{extract, ExtractionError, ExtractedCandid}` |

Normalization remains byte-bounded with the same whitespace/newline behavior and
now works without default features or Unix. Extraction retains its existing
default `candid-extraction` feature, Unix gate, source reinspection, tool admission
and process evidence. The parser is not added to the default extraction graph.

### Shared service and export facts

Enable `ic-interface` for parser-backed service inventory and IC method export
projection. With `default-features = false`, this adds generic Wasm facts and the
Candid parser without Host filesystem/process dependencies:

```toml
ic-host-tools = { version = "0.15", default-features = false, features = ["ic-interface"] }
```

`candid::service::inspect` accepts self-contained Candid text and `ServiceLimits`
with explicit source-byte and returned-method bounds. Grammar/type checking uses
the existing Candid parser, supporting aliases, constructors, quoted/escaped names,
comments and recursive types. Imports are refused; no files are resolved and no
diagnostics are printed. Invalid documents yield no partial inventory.

Results retain update/query/composite-query/oneway modes without expanding
argument types into another tree. Source bytes are bounded before parsing and
methods before result allocation. The parser still allocates and traverses source
types; these limits do not promise a hard heap, stack or CPU quota. Consumers
remain responsible for choosing appropriate source admission and resource policy.

`interface::exported_methods` projects borrowed method facts from
`ic_host_artifacts::wasm::WasmFacts`. It allocates nothing and neither reparses nor
type-validates Wasm. Non-function and lifecycle exports are excluded; internal
methods, empty names and names shared across modes are preserved for callers to
admit. No name is trimmed. `ServiceMethod::as_export` explicitly maps oneway to
the update namespace, allowing typed name/mode set comparisons.

Canic and IcyDB can replace their method-inventory parsing and export-prefix
decoding with these owners. Their expected interfaces, internal-export policies,
payload annotations, endpoint presentation and application reports remain local.
The implementation does not compare Candid argument types with Wasm signatures
or establish that an artifact is safe to install. Build/cache orchestration stays
in IC Build. Consumer migrations are separate from this library release and
coordinated through [Canic #458](https://github.com/dragginzgame/canic/issues/458)
and [IcyDB #307](https://github.com/dragginzgame/icydb/issues/307).

### Validation profiles

`make test-tools-interface` exercises the optional interface profile independently
of extraction. The complete gate includes it and verifies that pure text,
interface, limits and extraction feature graphs retain their declared boundaries.

### Contributor tooling

Adopt Shared Tooling 0.9.3 `3619de9dc36065411b8e6521f8695e9395a0e0ea`.
Explicit Host/IC asset downloads use curl's transient-error classification with
up to three retries, a two-second delay and a 60-second retry-start window.
Each attempt retains the existing 15-second connection and 300-second transfer
limits; an in-flight attempt may finish after the retry window. Permanent HTTP
errors and checksum/admission failures remain terminal. Failed candidates and
previous selections are preserved
([Shared #138](https://github.com/dragginzgame/shared-tooling/issues/138)).
This affects tool setup only; it adds no build deadline and changes no pins.
Existing verified installations need no reinstall.
