# IC Tooling 0.66

## [0.66.1] - Unreleased

### Current dependency and command examples

Build and Testkit installation guidance now selects 0.66 consistently, including
direct Host dependencies passed through Build. This corrects the older mixed
0.62/0.32 examples and Testkit's 0.64 selection beside its newer APIs.

The three Build executable examples use Clap for required positional arguments,
typed paths/digest values, help, version and error status. Missing and extra
arguments refuse before workspace or tool effects; the transactional example no
longer reports success for incomplete invocation. Valid positional invocations
are unchanged. Clap is a development dependency, so examples need no extra feature
flag and the default published library keeps its existing dependency boundaries.

### Shared Tooling

Refresh the same 137 payloads from Shared Tooling 0.26.9 at
`3657c044c0e91321effe8835989491a4cd0b5cba`. Tool pins and selected entrypoints are
unchanged. Explicit Cargo setup can wait for an admitted installer of the same
slot, tolerate that owner's normal lock cleanup, then recheck the current inputs
and selection. Missing or replaced claims still refuse; offline checks remain
immediate and do not repair or install anything. Cargo owns source-cache download
serialization instead of an extra global installation lock.

Contributors should rerun explicit `make install-rust-tools` once after adopting
the build-policy update, then use `make rust-tools-check` for offline admission.
Release-adapter qualification also needs `make install-release-editor` to prepare
the unchanged release-only editor pin.
Previous generations, source caches and failed attempts remain retained. This is
contributor setup, with no library API, package version or consumer-tool pin change.

## [0.66.0] - Unreleased

### Explicit PocketIC ownership transfer

`PocketIcInstance<T>` keeps its client and optional managed server private.
This prevents moving the client out through field projection and silently
stopping its server. Ordinary owner drop still drops a synchronous client before
terminating its managed server; no custom blocking or asynchronous destructor
is added. Upstream synchronous deletion can still block awaiting its response.

Replace `owned.instance` borrowing with `owned.instance()` and shared managed
server inspection with `owned.server()`. Keep the owner alive throughout client
use. There is no mutable client accessor or mutable server handle that permits
replacing either part while leaving an apparently intact owner.

To take over lifecycle ordering, call `let (instance, server) = owned.into_parts()`.
Retain `server` until the client is deleted. Nonblocking clients still require
explicit `instance.drop().await` before `drop(server)`; dropping their Rust owner
does not acquire automatic asynchronous deletion.

Replace `PocketIcInstance { instance, server: None }` with
`PocketIcInstance::from_borrowed_server(instance)`. This wraps the existing client,
performs no startup or connection, and acquires no server process ownership.
The external server must outlive that client. Upstream client deletion behavior
is preserved. Use startup configuration to construct a managed-server owner.

Canic's inspected startup adapter moves the client out with
`.map(|owned| owned.instance)`; it must deliberately transfer ownership and account
for the optional server. Its three direct borrowed-server constructions in the
standalone helper, root baseline and Fleet Registry baseline must use the named
constructor. Sibling sources were inspected read-only; their adoption is separate.

See [#237 — Make PocketIcInstance ownership transfer explicit](https://github.com/dragginzgame/ic-tooling/issues/237).
