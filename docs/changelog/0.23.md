# 0.23 — Shared text normalization and host I/O

## [0.23.2]

### Added

Host FS's Unix `copy` module copies held regular files or no-follow directory
trees into create-new private output. It returns exact per-file stream identities
and relative paths, preserving empty directories and refusing links, special
entries and non-UTF-8 names. The caller selects each file's byte allowance and
owns aggregate bounds, source/namespace custody, digest framing, synchronization,
publication and recovery. Partial output is retained. This extracts Backup's
filesystem mechanics without changing its checksum schema or Canic integration.
Native copy qualification exercises links, FIFOs, byte limits and retained output
on every host. Actual invalid UTF-8 entries are a Linux filesystem fixture;
all hosts retain exact non-UTF-8 error-path projection checks.

## [0.23.1]

### Added

Host Process's Unix `custody` module retains one regular sidecar lock through
one command and cooperating descendants. Callers select the path and descriptor
environment name, retain the returned device/inode identity before dispatch and
choose quiescence grace/polling. Existing-only quiescence refuses missing or
replaced identities; its non-spawning guard explicitly unlocks on drop.
Failed spawn consumes the one local allowance. No sidecar is removed or record
serialized; command admission, output/reaping, durable intent, paid spending,
remote outcomes and safe reference release remain caller-owned. This uses the
safe `command-fds` descriptor-inheritance API; native macOS consumer acceptance
and adoption from a published Host package remain separate.

Host FS admits an existing regular lock sidecar without creating a missing
entry and reuses the existing nonblocking descriptor lock. The directory
commit primitive accepts one caller-verified, synchronized tree, publishes it
by no-replace sibling rename, and synchronizes its parent. Recovery verifies
an already-canonical tree; errors after rename retain the visible name for
explicit reconciliation. Consumers retain checksums, journals, namespace
custody and retry authority. Backup adoption requires a published Host version
and its own qualification.

## [0.23.0]

### Breaking

Bounded line normalization moves from `ic_host_tools::candid::text::normalize`
to `ic_host_text::normalize::normalize_lines`. The old module is removed without
an alias. Import `NormalizationError` from `ic_host_text::normalize` as well.
Add a direct Host Text dependency when using this operation; Host Tools does
not acquire a production dependency on Text. Its extraction example and tests
select Text only as a development dependency.

The operation keeps its exact UTF-8, input/output-byte allowance, Unicode
trailing-whitespace, LF-ending, blank-line and fallible-allocation behavior.
Error variants and fields are retained at their new owner; display messages
describe generic text rather than Candid. It neither escapes terminal controls
nor validates Candid grammar. Callers continue selecting normalization explicitly.
Canic's compiled-declaration path must update its import after publication;
this source change does not qualify or change its selected registry graph.
Adoption remains in
[#458 — Adopt published IC Host Tooling](https://github.com/dragginzgame/canic/issues/458).

Missing-path resolution now has one entry point:
`ic_host_fs::path::canonicalize_allow_missing(path, base, max_symlink_depth)`.
The two-argument convenience and `canonicalize_allow_missing_with_symlink_limit`
name are removed without aliases. Pass the caller's existing depth allowance,
or select `usize::MAX` explicitly to preserve the old unlimited behavior.
This still bounds simultaneously active dangling-target expansions, rather than
path bytes, filesystem latency or native existing-target canonicalization.
Native traversal, cycle and completed-expansion behavior is retained.
Build's private cache adapter and Canic's output-root/backup adapters need the
explicit unlimited selection; Query's
export adapter retains its existing 64-depth choice and Governance smoke selects
unlimited expansion explicitly. These are source migrations after publication.

Explicit process failure diagnostics render each cleanup cause once through
the existing error display, removing the duplicate trailing `cleanup:` block.
Status, lossy/trimmed stdout and stderr, typed cleanup evidence and ordinary
error display are retained. Consumers with exact diagnostic assertions update
the expected text; parsing rendered errors remains caller policy.

The combined `lock_regular_file_with_parents` and
`try_lock_regular_file_with_parents` APIs are removed without aliases.
Call `open_regular_lock_file_with_parents` first, then `lock_exclusive` or
`try_lock_exclusive` on the returned descriptor, retaining it for the entire
protected operation. The latter attempts acquisition once and returns native
`WouldBlock` on contention without waiting or retrying. Shared locking and
caller-observed waits already use the same descriptor owner.

Preparation retains no-follow regular-file admission, durable creation of missing
parents/files, existing bytes and close-on-exec. Preparation errors remain
`RegularFileLockError`; descriptor acquisition returns `io::Error`. Callers
retain their error projection, contention policy, descriptor clones and final
unlock/close boundary. Splitting these steps adds no namespace confinement,
filesystem deadline, stale-lock deletion or recovery policy.

Build's immediate cache lock, Testkit's blocking setup lock and IC Crates'
immediate upload-spool lock must compose these operations after publication,
preserving their existing wait/busy and protected-lifetime behavior.

Owned process-group spawning now has one entry point:
`OwnedChild::spawn(command, cleanup)`. The one-argument convenience is removed;
the explicit-policy implementation replaces the `spawn_with_cleanup` name
without an alias. Pass `CleanupPolicy::KillAndWait` to preserve immediate KILL
and synchronous reaping, or retain the existing `TermThenKill` policy with its
caller-selected grace and reap allowances.

The selected policy still governs communication failure, explicit termination
and Drop. Natural waiting, retained-success admission and handoff are unchanged.
This introduces no execution deadline or finite limit on build duration.
Direct-child spawning/transfers retain their existing ownership and synchronous
cleanup; group capture retains its existing immediate KILL policy. Build's
bounded subprocess owner and Query's Governance smoke keep their policies;
Testkit's startup, downloader and fixture writer select `KillAndWait` explicitly
after publication. Consumer checkouts and selected graphs remain unchanged.

The combined `artifact::verify_reader` convenience is removed without an alias.
Use `hash_reader(reader, max_bytes)?.verify(expected)` to retain bounded hashing
and then admit the observed identity through its existing verification method.
This keeps one owner for each operation and returns the same `ArtifactError`
variants: read/limit failures precede digest comparison, while a mismatch retains
the expected digest and observed byte count/digest. The stream is read once;
verification does not reopen or rehash it. Trust selection, origin custody and
publication remain caller-owned. Testkit's authenticated PocketIC archive reader
needs this source update after publication, preserving its no-follow read and
authenticate-before-decode order. Its working source and graph are unchanged.

### Added

`ic_host_artifacts::wasm::code_statistics(bytes, module_bytes)` reports encoded
indirect calls, including `return_call_indirect`, and data-segment payload bytes
excluding section/segment framing. Input byte admission precedes decoding;
malformed operators or data return existing typed inspection errors without
partial statistics. No subprocess, instruction tree or new dependency is needed.
The existing `inspect` API remains unchanged and does not decode function
instructions.

This adapts [PR #146 — Encoded Wasm code and data statistics](https://github.com/dragginzgame/ic-host-tooling/pull/146)
for [#145 — Bounded encoded Wasm statistics](https://github.com/dragginzgame/ic-host-tooling/issues/145).
These are encoded statistics, not type/feature validation, optimizer reachability
analysis or an installability decision. IcyDB owns report field meanings and
must compare its selected artifacts and controls before replacing its Binaryen
metrics process. Callback text collection and feature/tool admission remain with
the consumer. Published registry adoption and consumer qualification are separate
from this additive Host source change.

`ic_host_text::progress::ProgressLine` constructs update, finish and clear frames
without IO. It escapes untrusted controls before summing Unicode scalar widths,
including wide and combining characters. Joined emoji count their component
widths conservatively, matching clipping rather than promising grapheme layout.
Shorter updates blank the previous columns; finish adds a newline and resets
the remembered width. Drop performs no IO.

This adapts [PR #158 — Pure terminal progress frames](https://github.com/dragginzgame/ic-host-tooling/pull/158)
for [#157 — Pure progress-line redraw frames for Query](https://github.com/dragginzgame/ic-host-tooling/issues/157).
Callers select byte/column limits, prevent wrapping, admit their terminal and
write the returned frames verbatim. They own flushing, write failures and when
to finish or clear; the helper does not observe whether a frame was written.
Query adoption must await publication and retains its own output qualification.

### Changed

Adopt Shared Tooling 0.16.0 at committed revision
`989752490b392f7f4c542c7652dcb84e75ecf363`. CI binary installation now requires
`--install-dir`; assertion-retention probes require explicit source, prefix and
contradictory bindings. Host has no invocation requiring either migration and
already uses the retained target-admission helper instead of the retired
exhaustive Make probe. Its target roster, substituted effects and jobserver checks
remain local. Standard exit probes retain all eight cases, including cleanup refusal.

`make cloc-tooling` and `CLOC_PARENT` are no longer exported by the consumer
include. Run fleet reports from Shared Tooling; Host retains `make cloc` and its
workspace/manifest routing. The updated setup guide describes optional TOML-backed
Rust toolchain preparation; Host's compiler policy and setup selection are unchanged.
Snapshot selection remains 88 entrypoints and 108 payloads. Common tool pins,
library versions and existing tool installations are preserved; no reinstall is
required by this adoption. Its contributor tooling changes add no library API break.

Root-relative reads and tree walking share private no-follow entry metadata,
open and descriptor-type operations. Their syntax, UTF-8 and unsupported-entry
policies remain at the existing callers. Directory-only/nonblocking opens,
descriptor checks and native error ordering are retained.

Durable pathname and descriptor entrypoints validate permissions and convert
them to the native mode once, then carry that admitted value through the private
publication engine. Invalid modes still refuse before parent creation/opening,
staging or producer execution. Filename, parent, staging identity/link-count,
cleanup and publication checks remain at their existing boundaries.

Synthetic HTTP capture carries checked bounds into its read loop and retains
the expected request length after header admission. Body fragments no longer
reparse the header. The original deadline, ambiguous/oversized header refusal,
trailing-byte checks and exact partial-byte evidence remain unchanged. This is
test-support cleanup, not a general HTTP parser or new transport policy.
