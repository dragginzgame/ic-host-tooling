# 0.28 migration

## 0.28.1

Enable `ic-host-artifacts`'s `wasm-validation` feature for full core-module
validation via `wasm::validate(bytes, max_bytes)`. This implies `wasm` and selects
the existing wasmparser dependency's validator; no parser, validator, feature-flag
or validated-type identities are re-exported. Errors preserve byte-limit refusal,
unsupported component encoding and an owned invalid-module diagnostic with its
source offset. Input-byte admission precedes parsing/validator allocation and does
not promise CPU or heap quotas.

The implementation validates complete modules, including every function body's
instructions, type consistency and index references, using the selected parser's
default supported proposal set. Existing structural inspection is unchanged and
the `wasm` feature alone does not select the validator. Consumers still own
target-specific feature admission, IC installation policy and deployment.

Testkit's two fixture-test Validator calls can become
`ic_host_artifacts::wasm::validate(&wasm, 100_000).unwrap()` with an explicit
caller-selected allowance and a dev-dependency selecting `wasm-validation`.
After both callers migrate, remove its direct wasmparser dev-dependency and unused
root catalog entry. This Host change does not modify Testkit or claim its adoption;
the supplying Host version must be published first.

## 0.28.0

`ic-host-tools` keeps empty defaults. Select `features = ["candid"]` for
`candid::decode` or `candid::service`; combine it with `ic-interface` when
comparing declared services with Wasm exports. The `certificate` feature selects
only bounded certificate decoding and certification identities. The `ic-interface`
feature interprets Wasm exports without requiring Candid parsing.

This is a breaking feature-contract change.
Query's certificate-only selection needs no parser. Canic and Build consumers of
Host Candid APIs must explicitly enable `candid` when adopting 0.28. No endpoint,
byte-budget, certificate-authentication or decoding policy changes.

The pending duration and non-Unix compiler fixes documented under
[0.27.7 preparation](0.27.md#0277) are retained in this next minor batch;
that historical preparation heading does not designate a separate release.

Enable the helper explicitly in a consuming manifest:

```toml
ic-host-tools = { version = "0.28", default-features = false, features = ["candid"] }
```

Certificate-only consumers use `features = ["certificate"]`; Wasm-only consumers
use `features = ["ic-interface"]`. Their combination also excludes `candid` and
`candid_parser` from normal/build dependencies. Agent and ledger-evidence profiles
retain their required codec through Platform without enabling Host's parser;
Registry uses Platform principal types without either codec or parser.

The other changes prepared under 0.27.7, including duration text, the MSRV CI
compiler fix and the native file CLI, ship together in 0.28.0. No separate
0.27.7 package is implied by those preparation notes.

### Initial publication admission

All six package MIT notices retain the canonical root copyright notices.
Publication fixtures now copy actual package notices instead of substituting the
root notice, so publication admission detects source drift during CI and the
complete release gate. No library API, feature, dependency selection or license
terms change. The notice correction follows the Git release tag; initial registry
publication records its exact corrected commit through package provenance. The
existing tag and release history remain intact.
