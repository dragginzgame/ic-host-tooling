# 0.28 migration

## 0.28.1

**Publication correction (2026-10-20):** the immutable 0.28.1 registry archive
does not contain the capability, scoped-file or full-validator batch described
below, and still uses Ciborium. The text records preparation, not delivered APIs.
Use 0.29.0 or later for those capabilities and the selected `serde_cbor` decoder;
see [the supplying migration](0.29.md). From 0.30 onward, FS callers must explicitly
select `capability` and/or `temporary-file`. The historical Minicbor/depth proposal
below was superseded; the final decoder has no caller-selected depth field.
See [#209 — Release notes advertise absent scoped temporary files](https://github.com/dragginzgame/ic-host-tooling/issues/209).

This compatible batch is prepared in
[PR #207 — Integrate the 0.28.1 batch](https://github.com/dragginzgame/ic-host-tooling/pull/207).
It must be integrated before release. The existing 0.28.0 Candid feature contract
remains unchanged; Query, Testkit and IcyDB adoption is separate from Host delivery.

### Capability filesystem operations

Unix FS adds owned directory/file-entry handles over private cap-std and
cap-fs-ext dependencies
([#80 — Capability-rooted filesystem extraction from Query](https://github.com/dragginzgame/ic-host-tooling/issues/80)).
Root selection and traversal reject symlink components. Relative creation,
regular-file opening, bounded enumeration and unlink/sync use held directory
handles; creation re-admits an AlreadyExists winner before parent synchronization.
Removal errors retain whether unlink completed. Existing descriptor readers and
durable publication remain the canonical implementations.

Query retains cache paths, filenames, identities, permission values, file-content
admission, aggregate/depth limits, candidate selection and public errors. Once its
cache adapters and discovery use Host's handles, Query can remove its direct
cap-* dependencies. This release does not migrate Query or promise non-Unix
filesystem execution.

### Full Wasm validation

Enable Artifacts' `wasm-validation` feature to call
`ic_host_artifacts::wasm::validate(bytes, max_bytes)`. It implies `wasm` and adds
full core-module validation, including instructions, types, indices and all
function bodies. Byte admission precedes parsing; components are refused and
errors retain owned diagnostics. Structural inspection remains independent:
`wasm` alone does not select the validator. Target-specific feature admission and
IC installation policy remain caller-owned.

Testkit can replace its two fixture-test Validator calls with this API and an
explicit byte allowance, then remove its direct wasmparser dependency. Consumers
must first select a published Host version that supplies the feature; upstream
parser and validator types are not re-exported.

### Scoped temporary files

Unix FS adds `scratch::TemporaryFile` over a private tempfile backend. Callers
select an existing parent and filename prefix, write through a standard file and
keep the guard alive while children use its absolute path. Creation is exclusive
with private permissions; drop attempts cleanup, including during unwinding, and
consuming `close()` returns removal errors. No durability or crash cleanup is
promised. Caller-retained scratch files and panic-retaining directory fixtures
keep their existing custody contracts.

IcyDB's CLI argument-file adapter can adopt the Host guard, retain its command
and error mapping, then remove its direct tempfile dependency. Parent selection,
bytes, budgets, child lifetime and recovery remain consumer-owned.

### Certificate decoder backend

Tools' certificate feature replaces Ciborium with Minicbor, already selected by
the ledger graph
([#201 — Replace the certificate Ciborium backend](https://github.com/dragginzgame/ic-host-tooling/issues/201)).
Public decoding signatures, Platform certificate/tree identities, strict fields,
tree tags/arities and byte/depth/trailing-data error categories remain unchanged.
The full caller-selected `u8` depth range and valid indefinite containers/byte
chunks remain supported. Malformed nested indefinite byte-string chunks now
refuse; the private native error source changes, so backend downcasts are not a
supported integration contract. Decoding still makes no authentication claim.

serde_cbor remains an independent development fixture encoder. Its fixed recursion
ceiling cannot preserve the production depth contract. Ciborium, ciborium-io,
ciborium-ll and unused half 2.x leave the release lockfile. Defaults stay empty;
certificate-only and certificate/interface normal/build graphs exclude Candid,
its parser, Agent transport and the fixture encoder. Query must adopt the supplying Host
release and refresh its lockfile to remove Ciborium from its own graph.

## 0.28.0

`ic-host-tools` keeps empty defaults. Select `features = ["candid"]` for
`candid::decode` or `candid::service`; combine it with `ic-interface` when
comparing declared services with Wasm exports. The `certificate` feature selects
only bounded certificate decoding and certification identities. The `ic-interface`
feature interprets Wasm exports without requiring Candid parsing.

This is a breaking feature-contract change.
The Platform-backed response-only graph reported in
[#200 — Keep response-only Tools free of Candid/parser dependencies](https://github.com/dragginzgame/ic-host-tooling/issues/200)
is covered by this boundary: response-only consumers select no Candid feature.
Query's certificate-only selection needs no parser. Canic and Build consumers of
Host Candid APIs must explicitly enable `candid` when adopting 0.28. No endpoint,
byte-budget, certificate-authentication or decoding policy changes.

The pending duration and non-Unix compiler fixes documented under
[0.27.7 preparation](0.27.md#0277) are retained in this next minor batch;
that historical preparation heading does not designate a separate release.

Enable the helper explicitly in a consuming manifest:

```toml
ic-host-tools = { version = "0.28", default-features = false, features = ["candid"] }
```

Certificate-only consumers use `features = ["certificate"]`; Wasm-only consumers
use `features = ["ic-interface"]`. Their combination also excludes `candid` and
`candid_parser` from normal/build dependencies. Agent and ledger-evidence profiles
retain their required codec through Platform without enabling Host's parser;
Registry uses Platform principal types without either codec or parser.

The other changes prepared under 0.27.7, including duration text, the MSRV CI
compiler fix and the native file CLI, ship together in 0.28.0. No separate
0.27.7 package is implied by those preparation notes.

### Initial publication admission

All six package MIT notices retain the canonical root copyright notices.
Publication fixtures now copy actual package notices instead of substituting the
root notice, so publication admission detects source drift during CI and the
complete release gate. No library API, feature, dependency selection or license
terms change. The notice correction follows the Git release tag; initial registry
publication records its exact corrected commit through package provenance. The
existing tag and release history remain intact.
