# 0.6 release notes

## 0.6.0 — pending

### Bounded capture with owned process-group cleanup

`tool::capture_group_command` captures a caller-configured command with the same
fair bounded stdout/stderr engine and deadline as `capture_command`, while using
`OwnedChild` to establish and clean a new process group. It signals remaining
same-group processes on natural leader exit, timeout, overflow or IO failure,
then reaps the leader. There is no automatic background handoff or retry
([#5](https://github.com/dragginzgame/ic-host-tooling/issues/5)).

This supplies the missing composition for Toko Miner's browser encoder wrapper:
its existing deadline previously reaped only the shell while a pre-exec Node
version probe could continue. Consumers opt in at their command boundary and
keep their own executable admission, environment, byte budgets and deadline.
Input remains null. This API does not implement Query's piped input, inherited
output, cancellation or successful-background-handoff orchestration.

Both capture entrypoints use one IO loop and cleanup projection. Existing
`capture_command` and admitted-tool execution retain direct-child cleanup.
The new group entrypoint replaces any configured process group with its own;
other command settings remain subject to the existing capture contract.
No dependency, unsafe-code boundary or on-disk format changes.

### Breaking error evidence addition

`ExecutionError` has a new public `group_error: Option<io::Error>` field. Update
consumer struct literals (use `None` for direct-child fixtures) and exhaustive
destructuring. The original failure, bounded output and observed status remain
separate from group-signal, fallback direct-child kill and reap failures. Error
display remains redacted; inspect typed cleanup fields for diagnostics.

Group cleanup is not process-tree confinement or a descendant-exit barrier.
Escaped processes and effects outside the group remain caller-owned. Credentials
can prevent complete signalling; cleanup failures must not be discarded or
treated as permission to repeat a paid operation. Spawning/setup and synchronous
cleanup may exceed the capture deadline. Native qualification and actual consumer
adoption are recorded separately in the [handoff](../status/current.md).
