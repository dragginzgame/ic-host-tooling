# 0.20 — Explicit admission, publication and borrowed Git observations

## [0.20.2]

The optional `icp-project` tools profile projects exact environment/network facts
from caller-bounded effective YAML produced by `icp project show`. It refuses
malformed/multiple documents, missing fields, duplicate identities, contradictory
map/name identities and empty names. ICP retains implicit-environment and recipe
resolution; callers retain executable admission, capture, funding and lifecycle.
Default tools graphs exclude the YAML parser
([#115 — Effective ICP environment facts](https://github.com/dragginzgame/ic-host-tooling/issues/115)).

## [0.20.1]

### Added

`ic_host_text::width::fit_line(line, columns)` escapes terminal controls before
fitting text to an explicit column allowance, returning an owned `String` and
adding `…` when clipped. Zero columns return empty text. Width uses the sum of
Unicode scalar widths, conservatively counting joined emoji separately; clipping
preserves UTF-8 boundaries without promising complete grapheme clusters.

This accepts the generic clipping mechanics proposed in
[#144](https://github.com/dragginzgame/ic-host-tooling/pull/144), adapted to the
current borrowed-or-owned escaping contract. Relay can replace its temporary Git
selection after publication; its queue presentation, dimensions, history, output
and redraw policy remain local. No dependency, terminal detection, filesystem or
process integration is added.

## [0.20.0]

### Breaking

#### Executable admission

Pinned executable admission now uses the same `VersionSpec` input as installed
version admission. `ToolSpec` is removed without a compatibility alias. Pass the
trusted digest separately as the second argument to `AdmittedTool::admit` or
`AdmittedTool::admit_no_follow`:

```rust,ignore
let tool = AdmittedTool::admit(&version_spec, expected_sha256, &context, limits)?;
```

The digest remains mandatory for pinned admission and is checked before version
execution. `admit_version` keeps its distinct caller-trusted installation policy.
Later byte-drift verification and final-symlink refusal remain unchanged. Build,
Testkit and IcyDB pinned callers must migrate when adopting this release; Host's
examples and tests use the new contract. No stored-data transition is required.

#### Git observations

`GitObservations::revision()` and `tree()` borrow the validated object IDs from
their retained captures, replacing the public owned strings. Successful captures
are private and available by shared reference through `revision_evidence()`,
`tree_evidence()` and `status_evidence()`. Update field access to method calls;
copy an ID explicitly only when the consumer needs independent ownership.
Object formats, exact raw output/diagnostics, query order, status-scope metadata
and failure evidence remain unchanged. This removes duplicated object-ID storage;
the returned observations still do not establish an atomic source snapshot.

#### Archive errors

Archive decoding now retains the gzip owner's errors through
`ArchiveError::Gzip(GzipError)`. Replace matches on `Decompression(source)` with
`Gzip(GzipError::Decode(source))`, and `TrailingCompressedData` with
`Gzip(GzipError::TrailingData)`. The error source chain includes `GzipError`
before its original artifact/native cause. Initial compressed-size and digest
admission remain `ArchiveError::Archive`; selected-member digest errors remain
`ArchiveError::Member`. CRC, truncation, inflation limits and rejection of
concatenated/trailing compressed data retain their existing behavior.

#### Named publication

`write_named_with(path, options, producer)` now accepts the existing `WriteOptions`
used by streamed publication. Callers select `PublicationMode` and staging
permissions explicitly; create-only publication refuses a competing destination
at the final publication boundary. Permissions still respect the process umask,
and owner-only staging does not establish private parent custody.

Canic's artifact transforms and IcyDB's optimizer currently need the equivalent
of their previous policy when adopting this release:

```rust,ignore
let options = WriteOptions {
    mode: PublicationMode::Replace,
    permissions: 0o666,
};
write_named_with(path, options, producer)?;
```

Named producers still receive the writable stage pathname and own completion and
output validation. Closed-writer admission remains the separate
`write_validated_with` contract. Typed producer/cleanup evidence and the
before/after-publication distinction remain unchanged; no automatic retry occurs.

#### Borrowed terminal text

`ic_host_text::escape::terminal_text` now returns `Cow<'_, str>`. Printable text
borrows the input, including Unicode, spaces and literal backslashes. Text needing
escaping owns the changed output. Table rendering retains these borrows while
measuring and aligning cells; rendered bytes and its owned `String` result are
unchanged. Control, Unicode separator and bidirectional escaping rules are retained.

Formatting and borrowed string use can consume the result directly. Call
`.into_owned()` when storing/returning a `String` or when an input will not outlive
the result. Query's String-returning text helpers need this explicit conversion
when adopting the release; Relay's direct formatting calls can retain borrows.
No dependency, persisted-data or terminal-policy change is introduced.

### Changed

- Descriptor locking shares regular-file admission and native dispatch across
  shared/exclusive acquisition and explicit unlock. Public operations, native
  errors, descriptor ownership and contention polling remain unchanged.
  Identical permission-denied artifact readers share private test support;
  partial-read and sink-failure fixtures retain their distinct assertions.
- Crash-barrier helpers share their polling loop, retaining marker-first success,
  child-exit precedence over timeout and the caller's selected wait duration.
  Inspector rendering converts output errors at one boundary after digest and
  Wasm admission; report bytes and typed output failures remain unchanged.
- Inspector CLI and IC limits example tests reuse the filesystem owner's fixture
  allocator instead of independent clock/PID naming and collision loops. The CLI
  keeps its existing evidence parent; the example owns a fresh temporary directory,
  removes it after success and retains it on panic. The CLI selects `test-support`
  only through its development dependency; production features are unchanged.
- Four unused Shared regression entrypoints are retired through the canonical
  exporter: evidence checksums, documentation links, file digests and Cargo
  metadata. Their implementation tests remain in Shared Tooling. Actual Host
  checkers and consumer/release/native qualification remain selected; common pins
  and retained helper bytes do not change.
- Host no longer replays Shared's synthetic host/IC/Rust installer and LOC parser
  matrices. Shared retains those regressions in its portable tooling suite. Host
  keeps its actual Make routing and ordered setup/check failures, LOC default and
  explicit-manifest arguments/status, jobserver behavior, snapshot integrity,
  prepared-tool admission and native acceptance. Canonical snapshot retirement
  removes the four unused matrices and their two unused fixture companions;
  the workflow's still-used Cargo cache-key helper remains explicitly selected.
- Identical invalid-count reader/writer test doubles share a private artifact
  test-support module. Each API retains its refusal/state assertions; prefix,
  interruption and flush-specific fixtures remain independent.
- Durable writes attach owned-stage cleanup evidence at one failure boundary.
  Producer errors, descriptor custody, value lifetime and before/after-publication
  distinctions are preserved; uncertain publication never enters ordinary cleanup.
- Git observations assemble ordered evidence in one place, preserving prior
  captures and malformed output without merging separate capture arrays.
  Public errors and query order remain unchanged.
- Tables append aligned cells and separators into one output string, removing
  intermediate padded-cell and rendered-line collections. Escaping, Unicode
  widths, empty rows and existing whitespace/newline behavior are preserved.
- Filesystem reads share Unix read-only, nonblocking, close-on-exec opening.
  Final-symlink refusal, optional-file absence and descriptor/size/private
  admission remain separate at their existing boundaries.
- Publication derives package directories from admitted Cargo metadata for both
  license and archive-provenance checks, supporting valid `crates/` and `apps/`
  placement without a second path roster. Invalid, escaping or aliased directories
  refuse before package preparation/upload; the publication allowlist is retained.
- The Wasm inspector accepts `--expect-sha256 SHA256` and `--details` after its
  existing positional budgets. Digest mismatch refuses before any report. Details
  append quoted export identities and custom-section names/sizes; default TSV
  output stays unchanged. Options are independent and may appear in either order.
- Shared Tooling now selects committed main `f5080b8` (0.15.2), including explicit
  fixture root/directory variables, observed-tool/evidence helpers and consumer
  qualification guidance. Host's ordering fixture uses the canonical dependency
  pair preparer instead of its local AWK implementation
  ([#134 — Shared Cargo ordering fixture](https://github.com/dragginzgame/ic-host-tooling/issues/134)).
  Common tool versions/digests and installed selections are unchanged.
- Release preparation and exact saved-payload checks use Shared's four-argument
  manifest renderer, retiring Host's AWK dependency projector
  ([#131](https://github.com/dragginzgame/ic-host-tooling/issues/131),
  [Shared #210](https://github.com/dragginzgame/shared-tooling/issues/210)).
  Host supplies parsed root/member identities from the selected Git source and
  its explicit workspace member paths, without rebuilding an old workspace or
  reading today's member manifests. Aliases, requirement operators/precision,
  unrelated bytes and exact candidate comparison remain supported. Existing
  validation receipt formats, rollback and publication boundaries are unchanged.

### Removed

The filesystem `inspect_artifact` example is retired. Use `ic-host-wasm-inspect`
with `--expect-sha256` and/or `--details` for its verification and inspection
capabilities. The filesystem development dependencies no longer select Wasm
inspection solely for this example; production dependency selections are unchanged.
