# 0.5 release notes

## 0.5.2 — pending

### Explicit successful background handoff

`OwnedChild::poll_exit` observes the leader's exit status without signalling or
reaping it. The exited leader remains reserved while the caller finishes bounded
IO, admits its result and checks cancellation. `OwnedChild::handoff` then reaps
only an exclusively owned leader that exited successfully, leaving its remaining
group running for the consumer's own stop/recovery operation
([#5](https://github.com/dragginzgame/ic-host-tooling/issues/5)).

Handoff refuses running, unsuccessful and already-reaped leaders. Observation
alone never disables cleanup: ordinary waiting, explicit termination and Drop
still signal the owned group. A refused handoff retains ownership unless an
external reaper has already violated it. Preserve the original operation/status
and any separate termination error. After successful handoff, cached waits,
termination and Drop never signal again. No PID/group cleanup handle is returned.

Use handoff only after the caller admits the command's output and accepts the
background lifetime; exit zero is not readiness or proof of completed effects.
Pipe draining/bounds, deadlines, signals, network identity and stop/recovery remain
consumer-owned. A cancellation racing after the explicit transfer belongs to
that consumer lifetime. This additive API preserves existing cleanup defaults,
dependencies and stored formats. Query's actual bridge/adoption and native
qualification remain separate from these primitives.

release-plan format and separate publication authority. No crate API, dependency
selection or package version changes. PR release delivery remains unselected.

## 0.5.0 — pending

### Explicit child and process-group cleanup

`ic_host_process::child::OwnedChild::spawn` starts a caller-configured command
once in its own process group. It preserves arguments, environment, directory
and IO, including piped input and inherited progress output. Callers can take
configured pipes, poll, wait for natural exit or terminate explicitly. Executable
admission, stream bounds, readiness, polling cadence, cancellation, deadlines,
signal handlers and application lifetime remain consumer-owned
([#5](https://github.com/dragginzgame/ic-host-tooling/issues/5)).

Natural exit retains the unreaped leader with `WNOWAIT` until remaining group
members have been signalled, then reaps and caches the leader's status. Drop
attempts cleanup during ordinary return or unwinding. Explicit termination
retains group-signal, direct-child fallback and reap errors separately, including
any observed exit status, so cleanup cannot replace the caller's original error.
Interrupted syscalls retry. Loss of exclusive reaping ownership fails closed.
macOS accepts a sole-zombie group permission result only after verifying that
the exited, unreaped leader is its only member.

The existing bounded capture engine uses the same child owner internally while
retaining its direct-child-only cleanup, null stdin, admission and evidence
contracts. This does not turn capture into a group runner or introduce implicit
cancellation. The child API is additive; the complete pending batch requires the 0.5 minor
release because of the artifact contract changes below.

Group cleanup is not process-tree confinement. Children must not change groups
and callers must not reap them independently. Escaped descendants, abrupt parent
termination, descendant exit completion and external-effect recovery remain
outside this contract. Cleanup is synchronous with no wall-clock guarantee.
After reaping, repeated calls do not signal again; callers must retain an earlier
cleanup error because a later cached status cannot repair lost group ownership.

The intended Testkit replacement removes its local child guard, polling,
group-termination and reaping mechanics while retaining PocketIC readiness,
output files and command/server policy. Source rehearsal is separate from
consumer adoption and native qualification; see the [current handoff](../status/current.md).
Query's higher-level capture/cancellation integration and Canic's inherited
operation-lock descriptors remain separate requirements within #5.

### Closed-writer executable admission

`ic_host_fs::durable::write_validated_with` streams and synchronizes a staging
file, closes its writer while retaining a verified read-only descriptor, then
runs the caller's admission callback before publication. Executable version or
environment probes can therefore run before replacing a working installation
([#20](https://github.com/dragginzgame/ic-host-tooling/issues/20)).

The existing commit engine owns both replace and create-only publication,
identity checks, cleanup and file/parent synchronization. Producer and admission
errors retain their original type and separate cleanup errors. Filesystem errors
retain before/after-publication evidence. Callers must close all writable clones,
finish child processes, select permissions and exclude concurrent namespace or
content mutation. This is single-file publication, not bundle installation.

### Breaking artifact contracts and IC resource reports

`encode_gzip` takes a numeric compression level in `0..=9`, removing the public
`flate2::Compression` dependency type. Replace `Compression::best()` with `9`,
`fast()` with `1`, `none()` with `0`, and `default()` with `6`. Invalid levels
fail before writing any output. Valid settings retain the selected backend's
existing bytes; tests may still use flate2 as an independent oracle
([#14](https://github.com/dragginzgame/ic-host-tooling/issues/14)).

`WasmFacts` adds `code_body_bytes`, `imported_functions`, `defined_globals` and
`imported_globals`. Update struct literals and exhaustive `InspectionError`
matches for `CountOverflow` and `UnrepresentableSize`; address-space conversion
failure is no longer misreported as a caller's module-size limit. Import/global
vectors are now parsed, so malformed vectors are rejected. This remains
structural inspection rather than instruction/type validation
([#10](https://github.com/dragginzgame/ic-host-tooling/issues/10),
[#14](https://github.com/dragginzgame/ic-host-tooling/issues/14)).

The opt-in `ic-host-tools` feature `ic-limits` exposes `install_limits` with an
explicit revision-bound `REFERENCE_LIMITS` and caller-selected `InstallLimits`.
Reports compare code-body bytes, defined functions and total globals, providing
exact usage, inclusive limits and signed headroom. The reference is IC commit
`9499f64bda8bcf087188dd8a1bb594115640ba9e`: 12 MiB, 50,000 defined functions and
1,000 globals. It is not a claim about every deployed target. Callers select
reference values or overrides and retain warning/admission policy
([#10](https://github.com/dragginzgame/ic-host-tooling/issues/10)).

The replica's code measurement excludes the encoded function-count prefix.
The existing `code_section_bytes` metric includes it and is preserved for
reporting; replica comparisons must use `code_body_bytes`. Function imports do
not consume the defined-function allowance; imported globals do consume the
global allowance. These three comparisons do not cover metadata, module/upload
size, supported imports/features or all other installation checks. A passing
report does not establish installability. With defaults disabled, `ic-limits`
requires only the artifact owner, without filesystem/process dependencies.

No stored format, manifest version or selected dependency version changes.
Consumers must select the published 0.5 line after release and qualification.
Native macOS evidence for the pending code is tracked in the current handoff.
