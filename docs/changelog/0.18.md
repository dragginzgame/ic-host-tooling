# 0.18 — Private-parent path admission

## [0.18.0]

`ic_host_fs::durable::prepare_private_parents` now checks every existing path
component before creating missing directories. An existing descendant reached
through a symlink is rejected, as is a `..` component. Previously, the helper
could accept that path even though its documented contract promised symlink
refusal. Callers that intentionally used an ancestor directory alias must pass
a canonical physical path instead. The caller still owns root confinement and
exclusion of concurrent namespace mutation; this check does not make pathname
traversal race-free.

Owner-only `0700` creation, synchronization of each new directory and parent
link, and ordinary parent modes in other Host FS writers are unchanged.
Refused paths retain existing symlinks/files and create no missing directory,
including a missing component preceding `..`.
([PR #90 — Reject symlink ancestors](https://github.com/dragginzgame/ic-host-tooling/pull/90)).
