# 0.18 — Descriptor admission and bounded host mechanics

## [0.18.2]

- Add `durable::copy_from` using the existing named writer. Callers select the
  reader, its limits, publication mode and optional exact permissions; default
  creation/umask behavior remains available. Exact permissions are applied after
  copying so writing cannot clear selected set-ID bits. Read failure and create-only refusal
  preserve existing output bytes; existing typed publication phases remain
  unchanged ([#92 — Share durable stream copying](https://github.com/dragginzgame/ic-host-tooling/issues/92)).

## [0.18.1]

### Fixture allocation and resource-report examples

`ic-host-fs` adds `testing::create_fixture_directory(parent, prefix)` behind the
opt-in `test-support` feature. It uses an existing physical parent, creates a
fresh owner-only Unix directory and skips collisions without reclaiming entries.
Callers retain naming, custody, cleanup and failed-evidence policy. Filesystem,
process and tools fixtures share the allocator, with their existing serialization
guards and Drop retention unchanged. Select the feature in a development
dependency; it adds no automatic production lifecycle
([#98 — Fixture directory allocation](https://github.com/dragginzgame/ic-host-tooling/issues/98)).

The resource-report example uses the canonical bounded regular-file reader,
including early size admission and nonblocking Unix FIFO refusal. File failures
now retain the artifact reader's typed cause. Text/JSON fields, explicit limits,
reference comparisons and failure exits are unchanged. Its valid-fixture builder
delegates unsigned LEB128 encoding to the already locked dependency, selected
only for development. Artifact encoder golden/malformed fixtures remain
independent; no production library dependency is added
([#106 — Resource-report example cleanup](https://github.com/dragginzgame/ic-host-tooling/issues/106)).

### Raw hashing and maintenance fixtures

Raw payload identification hashes the borrowed slice directly after its input and
payload allowances, avoiding the stream traversal buffer. Compressed input keeps
the existing single-member decoder and bounded hashing. Digest/length results,
input-limit precedence, typed payload-limit errors and malformed-gzip refusal
remain unchanged; no caller migration is required.

Publication fixtures derive package names and paths from independently prepared
original Cargo metadata. The production publication allowlist, provenance checks
and exact command assertions remain separate. Host's failure-retention fixtures
reuse Shared's existing exit probes from the pinned 0.12.7 revision, retaining
Host's roster, actual round trips and contradictory release assertions. The
snapshot gains that helper without changing the baseline or tool pins
([#105 — Raw hashing and fixture simplification](https://github.com/dragginzgame/ic-host-tooling/issues/105)).

## [0.18.0]

### Breaking: following-file refusal order

`read::read_file` and `hash_file` now open once before checking the descriptor's
regular-file type and size. `open_regular_file` shares that same admission path.
An inaccessible oversized file therefore returns its native open error before a
byte-limit error. Callers must handle open failures before interpreting metadata
rejection; final-symlink following remains intentional. Unix nonblocking/CLOEXEC
flags, descriptor ownership and bounded stream checks for growth remain intact
([#96 — Archive, read and lock projection](https://github.com/dragginzgame/ic-host-tooling/issues/96)).

### Archive and release simplification

Immutable archive/member slices use the existing digest computation and identity
verification without a buffered reader. Compressed-input allowance and digest
admission still precede decompression; literal member selection, complete tar/
gzip checks, mismatch identities and fallible result allocation remain unchanged.

Only saved-source Cargo.lock projection moves to the selected Shared 0.12.7 lock
rewriter. Host's exact manifest/dependency spelling, receipt/notes checks and older
release-commit recovery stay local. Original coordinated lock versions are
admitted by the existing TOML reader during preflight, without invoking a
same-version rewrite. External lock selections remain untouched ([#96 — Archive, read and lock projection](https://github.com/dragginzgame/ic-host-tooling/issues/96)).

### Additional host capabilities and tooling

Durable private-directory creation returns a retained descriptor and preserves
before/after-creation failure phases. Pathname admission checks the current
no-follow directory against that descriptor; root confinement, trusted ancestors,
namespace exclusion, record policy and recovery remain consumer-owned.

Buffered child-output completion accepts the original stdout reader, retaining
prefetched protocol bytes under the existing output bounds. Reaped/terminated
children return their cached status without signalling again; transferred owners
refuse. Original capture/cleanup semantics and ordinary communicate calls remain
unchanged ([#94 — Directory and buffered-output custody](https://github.com/dragginzgame/ic-host-tooling/issues/94)).


Adopt Shared Tooling 0.12.7 at `9364ffe3f770a6d5d94809f0bf82c33202054bf8`.
Release-note guidance separates coherent outcomes and upgrade actions while
keeping issue coverage at its owning entry. New guides describe optional
documentation-only CI selection and explicit Rust toolchain preparation; Host's
native workflow, executable snapshot payloads and tool pins are unchanged.
No reinstall or library consumer migration is required
([#73 — Shared Tooling adoption](https://github.com/dragginzgame/ic-host-tooling/issues/73)).

`wasm::encode_custom_section` takes a borrowed `CustomSection` and an explicit
complete-section byte allowance. Name and payload lengths are admitted in Wasm's
u32 domain before fallible allocation; `CustomSectionEncodingError` preserves
length, byte-limit and allocation categories. Minimal unsigned integer framing
delegates to the existing locked `leb128` package under the optional Wasm feature.
Exact UTF-8 names, arbitrary payload bytes and caller-selected duplicates/order
are preserved. Callers retain module assembly, aggregate budgets, validation and
metadata schemas. Independent parser-malformation fixtures stay intact; no
runtime, filesystem/process or Candid policy moves into the encoder
([#77 — Bounded Wasm custom-section encoder](https://github.com/dragginzgame/ic-host-tooling/issues/77)).
