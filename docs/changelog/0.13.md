# 0.13 release notes

## [0.13.2]

### Contributor tooling

Adopt Shared Tooling 0.5.0 `a306180ce534227fcb98b882fba9a526d5d747e0`
([Host #63](https://github.com/dragginzgame/ic-host-tooling/issues/63),
[Shared #118](https://github.com/dragginzgame/shared-tooling/issues/118)).
This is a compatible library update: the published APIs, behavior, dependencies
and MSRV remain unchanged. Contributor setup changes do not require a library
minor release. The canonical snapshot now records the corrected source version
([Shared #119](https://github.com/dragginzgame/shared-tooling/issues/119)).

Common formatters and candid-extractor use the same versioned installation,
Cargo receipt and byte-admission engine as selected Cargo executables. The common
PATH activates only after all three tools pass. Host's CI, shared Make commands,
formatting hooks and setup instructions use `.tools/rust/common/bin`.

After preparing the host tools and Rust toolchain, run:

```sh
make install-tools
make tools-check
export PATH="$PWD/.tools/host/bin:$PWD/.tools/ic/bin:$PWD/.tools/rust/common/bin:$PATH"
```

Old `.tools/rust/bin` files, Cargo receipts, successful slots and failed attempts
are retained. The old PATH is no longer admitted as the common toolset; there is
no fallback or automatic cleanup. CI failure evidence retains the full physical
Rust tool tree. Host's selected cargo-edit version and release adapter remain
unchanged, as do tool pins and all four library APIs.

Host and IC tools now use Shared Tooling's verified per-user store
([Shared #120](https://github.com/dragginzgame/shared-tooling/issues/120)).
The default is `${XDG_DATA_HOME:-$HOME/.local/share}/shared-tooling/tools`;
an absolute `SHARED_TOOLING_STORE` selects another location and must match across
setup, offline checking and evidence collection. `.tools/host/bin` and
`.tools/ic/bin` remain the command paths, backed by references to exact shared
generations. Matching pins/platforms reuse authenticated bundles; another
checkout's setup cannot retarget an existing selection. Prior local bundles and
failed attempts are retained, with admitted shared evidence collected per checkout.
Host's native tooling gate now runs the adopted IC installer regression alongside
the host installer, including shared-selection reuse and corruption refusal.
Explicit setup is required to adopt the new storage admission. Cargo slots and
build output remain local under `.tools/rust`; sharing compiled tools still needs
an upstream build-identity contract. Do not relocate or delete old bundles manually.

Snapshot refresh offers a read-only `--preview` for file actions and missing
transitive companions. Staging, package versions, commits, tags and release
execution remain user-owned unless explicitly delegated.

## [0.13.0]

### Breaking: caller-owned lock progress

Remove `ic_host_fs::durable::lock_file_with_progress`, including its fixed 100 ms
polling and one-second reporting policy
([#60](https://github.com/dragginzgame/ic-host-tooling/issues/60)). There is no
compatibility alias. Compose `open_regular_lock_file_with_parents` with
`lock_exclusive_with_wait`, keeping the returned file alive throughout the
protected operation. Callers select polling, report cadence and callback errors.

The opener retains `RegularFileLockError` for admission/publication failures;
the descriptor wait returns the original `io::Error` for acquisition or callback
failure. Callers returning `io::Result` can project the opening error with
`io::Error::from`. Existing pathname blocking and nonblocking APIs are unchanged.

To preserve the old timing behavior in a consumer that supplies a fallible
`report(&File, Duration)` callback, use the following inside an `io::Result`
function, with the usual `std::time::{Duration, Instant}` imports:

```rust,ignore
let started = Instant::now();
let file = open_regular_lock_file_with_parents(path).map_err(io::Error::from)?;
let mut next_report = Duration::from_secs(1);
lock_exclusive_with_wait(&file, Duration::from_millis(100), |_| {
    let elapsed = started.elapsed();
    if elapsed >= next_report {
        report(&file, elapsed)?;
        next_report = elapsed + Duration::from_secs(1);
    }
    Ok(())
})?;
// Keep `file` alive while performing the protected operation.
```

The timer includes opening, as before. The descriptor wait reports contention
before each sleep; without the consumer's throttle it can report immediately.
Callback failure leaves that borrowed descriptor open and unacquired; the caller
owns its lifetime. Retain any post-acquisition cancellation check before mutation.
No finite build deadline is introduced. Lock files, advisory metadata and recovery
state need no reset, replacement or format migration.

Canic's build-reuse lock is the observed production consumer. It can adopt this
composition with existing 0.12 dependencies before selecting 0.13. Other consumers
must remove calls to the retired API when updating their compatible dependency
requirements to the new minor line.
