# 0.24 — Build-owned extraction and shared buffer growth

## [0.24.1]

### Added

`ic_host_text::table::render_bordered` shares escaped borrowed cells, Unicode
column widths and padding with plain tables. Dynamic rows may omit cells or
add unnamed columns; header-only reports retain the border separator. Callers
retain input/output allowances, SQL value semantics and report composition.
No dependency or package metadata changes are introduced by the table extension.
This extends [#110 — Terminal-safe text and table ownership](https://github.com/dragginzgame/ic-host-tooling/issues/110).

## [0.24.0]

### Breaking

Native Candid extraction moves from `ic_host_tools::candid::extraction` to
`ic_build::artifacts::candid`. Host removes the `candid-extraction` feature,
native extraction example and extraction-specific test profile without aliases.
Tools retains Candid service inspection, IC export projection and response decoding;
its production graph no longer has filesystem or process dependencies.

Publish the Build implementation before releasing this Host removal. Consumers
must select that Build release, move extraction imports, remove the retired Host
feature and align directly supplied Host types with Build's selection. Build's
MSRV is 1.91; generic Host libraries retain 1.88. Source/tool selection, exclusion
of concurrent writers, environment, byte limits, optional deadlines, normalization,
grammar and publication remain caller-owned. The move preserves raw output and
source/tool identities, complete successful output admission, and source-change
or reinspection errors with retained process evidence. Before/after hashes do
not detect transient writes and never replace the caller's source lease.

[Build #51 — Own native Candid extraction](https://github.com/dragginzgame/ic-build/issues/51)
owns the producer move, prepared in
[Build PR #52 — Move native Candid extraction](https://github.com/dragginzgame/ic-build/pull/52).
The additive Build producer initially retains Host 0.23 types; after Host 0.24
publication, Build must align its exposed Host selection before consumers upgrade
the complete Host graph. Published Canic adoption remains in
[#458 — Adopt published IC Host Tooling](https://github.com/dragginzgame/canic/issues/458);
IcyDB adoption remains in
[#307 — Adopt split Host owners](https://github.com/dragginzgame/icydb/issues/307).
Canic retains its normalized declaration/cache policy; IcyDB retains exact raw
UTF-8 artifact text. No retained artifact or manifest format is changed here.

`artifact::hash_gzip_or_raw` is removed without a replacement wrapper or alias.
The sibling scan found no production caller; strict streaming `hash_gzip`
remains in use by Testkit and is retained. Select `hash_reader` for raw streams
and `hash_gzip` for a selected gzip member. Callers retaining format detection
own that decision and must preserve both complete-input and payload allowances;
magic bytes no longer select a representation inside Host. Gzip header, CRC,
length, decoded-limit and trailing-data checks remain at their existing owner.

### Added

`VersionObservationSpec` and `AdmittedTool::observe_version` record a
caller-trusted installed executable's byte identity and trimmed version through
one version invocation. No independently selected version or digest authenticity
is implied. The shared admission engine hashes before dispatch, requires complete
successful nonempty UTF-8 output and rechecks retained bytes before later runs.
Existing exact-version, digest-pinned and no-follow admission remain unchanged.
Empty observations retain the capture in `ToolError::VersionMismatch`; process,
UTF-8 and truncation failures keep their existing typed evidence. Consumers retain
paths, trust, arguments, environment, byte allowances and optional deadlines.

This adapts [PR #167 — Observe installed versions with one admission probe](https://github.com/dragginzgame/ic-host-tooling/pull/167)
for [#166 — Observe installed tool version with one provenance probe](https://github.com/dragginzgame/ic-host-tooling/issues/166).
[Testkit #112 — Adopt single-probe observed-version admission](https://github.com/dragginzgame/ic-testkit/issues/112)
owns removal of its preliminary version capture after published adoption.

`ic_host_fs::owned_directory::OwnedDirectory` holds explicit invocation cleanup
responsibility for one caller-selected pathname. Construction creates nothing
and establishes no ownership. Armed Drop attempts cleanup; preservation/disarming
transfers recovery, and explicit cleanup retains the first I/O error while
leaving Drop armed for best-effort retry. The shared `remove_path_if_present`
accepts an initially absent entry, recursively removes a selected directory or
unlinks another final entry without following its symlink. Callers must own
namespace/ancestor custody and destructive-operation policy. No pruning,
allocation, durable publication or consumer lifecycle is added.

This adapts [PR #160 — Share invocation directory custody](https://github.com/dragginzgame/ic-host-tooling/pull/160)
for [#159 — Own invocation directory custody for Build](https://github.com/dragginzgame/ic-host-tooling/issues/159).
[Build #49 — Relocate directory custody](https://github.com/dragginzgame/ic-build/issues/49)
retains published adoption and deletion of its local guard/removal mechanics.

### Changed

`ic_host_artifacts::artifact::buffer::reserve_bounded` reserves fallibly for
up to the remaining element allowance and returns the number admitted. It does
not append, truncate or shrink existing storage. Stream reads, chunk digests and
process capture share its growth algorithm. Callers retain distinct overflow
policy and typed allocation errors; Process still drains or terminates according
to the selected output limit and retains observer/truncation evidence.

Publication tests retain one logger-failure delegation case proving that Host
propagates Shared's status and releases both preparation/core locks. Shared owns
the complete Cargo/logger status-precedence matrix;
[Shared PR #250 — Qualify publication logger status](https://github.com/dragginzgame/shared-tooling/pull/250)
adds its missing retained logger-status assertion. Host retains its package
selection, source/archive provenance, fetch and interruption/recovery checks.

### Other pending additions and tooling

Artifacts `Sha256Digest::hex_bytes` returns exactly 64 lowercase ASCII bytes in
a fixed-size buffer without allocation. Display uses that same encoder and keeps
its existing formatting behavior. Leading zeroes, raw SHA-256 identities and
parser acceptance are unchanged. The method is available in const contexts
without optional features or another dependency.

This adapts [PR #163 — Fixed-buffer SHA-256 output](https://github.com/dragginzgame/ic-host-tooling/pull/163)
for [#161 — Share fixed-buffer SHA-256 hexadecimal output with Build](https://github.com/dragginzgame/ic-host-tooling/issues/161).
Build can remove its per-file temporary hexadecimal String after publication;
its inventory ordering and big-endian field framing remain local. Published
adoption and consumer qualification remain in
[Build #50 — Simplify grouping, snapshot metrics and digest encoding](https://github.com/dragginzgame/ic-build/issues/50).

`ic_host_fs::read::read_file_prefix(path, max_bytes)` returns a bounded raw
prefix and the descriptor length observed during regular-file admission.
Unlike complete-file reads, a longer file is permitted; no bytes beyond the
prefix are read. Zero limits still perform opening and type admission. The
existing opener supplies symlink following and Unix nonblocking FIFO rejection;
allocation remains fallible through the bounded artifact reader. Existing
complete-file reads retain their early size rejection and error ordering.

This adapts [PR #155 — Bounded regular-file prefix reads](https://github.com/dragginzgame/ic-host-tooling/pull/155),
reusing the admitted metadata observation instead of querying the descriptor
again for length. Concurrent writers can still change contents and length after
that observation; this is no snapshot or filesystem deadline. Consumers retain
limits, decoding, truncation text and error presentation. Testkit can replace
its local startup-log read composition after publication, retaining its own
lossy decoding and omitted-byte messages.
