# IC Tooling 0.63

## [0.63.1]

Build optimizer qualification selects only `wasm-opt` in Make and direct offline
admission. Shared's complete catalog and receipt checks remain authoritative.
Native/release aggregates still select no IC executable setup, and existing
optimizer execution, three-host qualification and full failure retention remain.
No product API, pins, compiler or lock selection changes. The snapshot records
committed Shared 0.26.2; exact-source producer and consumer hosted acceptance
remain required before integration
([#224 — Select only wasm-opt for Build optimizer qualification after Shared 0.26](https://github.com/dragginzgame/ic-tooling/issues/224)).

## [0.63.0] - Unreleased

### Breaking: opt in to command-line binaries

Build's `ic-build-release-metadata` and Testkit's `ic-testkit-server` now require
the `cli` feature. Add `--features cli` to their Cargo install/build/run commands
and to explicit CLI integration-test selections. Binary names and behavior are
unchanged. Default library consumers no longer acquire Clap from either crate.
Workspace setup targets select the feature automatically. Shared Tooling's
lockfile-selected installer also accepts `--features cli`; pass it for these
binaries when selecting 0.63 or later. The separately pinned 0.18.0 release editor
keeps its existing installation recipe until its explicit tool-pin upgrade.

### Breaking: benchmark arithmetic belongs to Testkit

Replace references to `ic_metrics::MeasurementRatioError` from Testkit benchmark
calls with `ic_testkit::benchmark::BenchmarkAverageError`. The `ZeroDenominator`
and `Overflow` variants retain their meaning, including zero-run rejection at
scale zero and floor rounding without intermediate multiplication overflow.
Testkit no longer depends on IC Metrics, which belongs at the Canic capability
layer rather than beneath tooling. No compatibility reexport is retained.

### Breaking: Testkit no longer owns Candid calls

Remove uses of `query_candid_args`, `update_candid_args`, `CandidCallError` and
`CandidCallContext`. For owned application endpoints, enable Testkit's `wire`
feature and migrate client and canister together to the existing `query_wire` /
`update_wire` method contracts. This does not reinterpret existing Candid bytes
as Wire or change initialization bytes automatically.

For externally defined Candid interfaces, consumers own their direct Platform
codec dependency, argument encoding, bounded reply decoding and error projection.
Use PocketIC's raw byte operations; wrap only transport execution in
`try_pocket_ic_operation`, leaving application codec failures outside that scope.
The existing classifier preserves typed Wire codec/rejection boundaries; it no
longer recognizes consumer-owned Candid decoder types specially.

Testkit no longer enables Platform's `candid` feature or carries its own Candid
adapter. PocketIC still requires Candid transitively. The deployed Wasm profile
remains Candid-free. There are no compatibility reexports or fallback codecs.
This requires a coordinated minor release; the workspace version is not bumped
by these local changes.

[#223 — Remove Testkit-owned Candid call APIs and codec coupling](https://github.com/dragginzgame/ic-tooling/issues/223)

### Tooling

- Adopt IC Platform and macros 0.6.0. Host's registry feature and Testkit
  explicitly request Platform's newly optional principal capability, preserving
  their native and Wasm APIs without enabling Candid or runtime features globally.
- Wire calls use the existing transport panic boundary directly after removal
  of the Candid adapter; rejection and unrelated-panic handling are unchanged.
- Testkit requests Tokio runtime/network features only for its test harness;
  production code requests timers. PocketIC still enables runtime/networking
  transitively, so this does not change the resolved native dependency set.
- Publication and archive qualification read one public-package selection
  ([#220 — Share public package selection](https://github.com/dragginzgame/ic-tooling/issues/220)). Focused runtime
  jobs prepare only PocketIC ([#221 — Narrow runtime CI setup](https://github.com/dragginzgame/ic-tooling/issues/221));
  development CI reads the existing Rust/Node version files
  ([#222 — Read CI versions from existing owners](https://github.com/dragginzgame/ic-tooling/issues/222)). MSRV and the
  independent qualification stages remain unchanged.
- Adopt Shared Tooling 0.25.9 at `85aded191d85ac4a8c0e5deab207f6be18895862`.
  A committed but undelivered release preparation now refuses another increment
  and preserves recovery evidence. Tool pins and public APIs are unchanged
  ([Shared #292 — Prevent committed preparation incrementing twice](https://github.com/dragginzgame/shared-tooling/issues/292)).
