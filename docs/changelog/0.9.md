# 0.9 release notes

Release dates and draft status are recorded in the [root ledger](../../CHANGELOG.md).

## 0.9.6

Plain and labeled response hex now use the same validation pass for digit
admission, empty-text rejection and decoded-size checks. Remove the private
`response::decode_text_hex` wrapper and its separate whitespace scan. JSON still
accepts an empty `response_bytes` string, while text formats require digits;
whitespace, labels, error precedence and allocation bounds are unchanged.
No consumer migration or dependency change is required.

## 0.9.5

Adopt Shared Tooling 0.2.7 `47d6ae6488b8007323fa7c2e22a6efa11d77ae63`, adding
`make/execution.mk` to the 88-file snapshot. Shared release and formatting
includes reject ignore-errors, dry-run, touch and question modes before recipes
can run or failures can be ignored. Ordinary and parallel Make retain their
existing command selections. The redundant local `format-execution-check`
target is removed; direct script entrypoints retain their independent guards
([#42](https://github.com/dragginzgame/ic-host-tooling/issues/42),
[shared #30](https://github.com/dragginzgame/shared-tooling/issues/30)).

Host binds `SHARED_TOOLING_ROOT` to its current checkout before loading the
shared includes. Environment, command-line and recursive Make selections cannot
redirect its parse-time admission helper, formatter prerequisites or release
runner to an external snapshot. A Host adoption fixture exercises these paths
with substitute effects and rejects unsafe execution modes
([#42](https://github.com/dragginzgame/ic-host-tooling/issues/42)).

Release-command qualification explicitly binds its substitute runner to the
temporary checkout, preventing inherited tooling-root settings from selecting
an external runner. Its isolated Makefile export includes the new guard and
behavioral probe ([#42](https://github.com/dragginzgame/ic-host-tooling/issues/42),
[shared #7](https://github.com/dragginzgame/shared-tooling/issues/7)).

Formatting-hook qualification preserves newline-ending root paths and quotes
Git object-directory alternates correctly; the production hook's existing
pathname behavior is unchanged
([shared #90](https://github.com/dragginzgame/shared-tooling/issues/90)).
Release policy, library APIs, dependency selections and tool pins are unchanged.

## 0.9.4

Adopt Shared Tooling 0.2.6 `ce13a5314916891fd239d9b199b4a91b04775054` and its
optional `make/release.mk` and `make/rust-format.mk`, extending the snapshot
selection from 85 to 87 files. Standard release increment/resume routing,
conflicting-goal admission and Rust formatting recipes now have shared owners
([#41](https://github.com/dragginzgame/ic-host-tooling/issues/41),
[shared #91](https://github.com/dragginzgame/shared-tooling/issues/91),
[shared #92](https://github.com/dragginzgame/shared-tooling/issues/92)).

Host retains direct-only release admission, its local release adapters and
validation, and its formatting execution/failure-propagation guard. Formatting
uses prepared tools offline and resolves Cargo through the recipe's exported
PATH. Default `make` remains help; setup, hook activation and publication remain
explicit. Package versions, tool pins and Rust library contracts are unchanged.

## 0.9.3

The Shared Tooling snapshot advances to committed 0.2.5
`04e07b4bf54e7aeb03eb7804a845cee27b7305df`, retaining its 85-file selection.
Hook installation compares configured paths literally, including trailing
newlines, and refuses conflicting local or inherited selections without changing
configuration. Installation and pre-commit execution preserve newline-ending
checkout paths; failed Git observations still stop setup
([#40](https://github.com/dragginzgame/ic-host-tooling/issues/40),
[shared #89](https://github.com/dragginzgame/shared-tooling/issues/89)).
Hook activation remains explicit. Rust APIs, dependencies and tool pins are unchanged.

## 0.9.2

CI uses a separate concurrency group for each pushed commit so later main pushes
do not cancel its queued or running native qualification. PR updates retain a
stable group and can cancel superseded review revisions
([#39](https://github.com/dragginzgame/ic-host-tooling/issues/39)). This preserves
future evidence; it does not restore already-cancelled checks or add runner capacity.

The Shared Tooling snapshot advances to committed 0.2.2
`ee48bb37c98c771e77b92fd891f0757d8c1c8b99`, preserving its 85-file selection.
IC installation and offline verification consume the final pin row even without
a trailing newline ([shared #87](https://github.com/dragginzgame/shared-tooling/issues/87)).
CI tool publication uses an exact-path atomic rename, refusing
a late directory and replacing a late symlink without touching its target. Perl
is checked before downloading; existing local setup already requires it
([shared #88](https://github.com/dragginzgame/shared-tooling/issues/88)).
Tool pins, Rust library APIs, package versions and dependency selections are unchanged.

## 0.9.1

Durable byte, streamed and named publication use `WriteOptions` directly. Remove
the private `FileCommitMode` enum and its `commit_with_producer_and_hook`
translation wrapper; named producers call the existing options-based engine.
The convenience functions retain their replace/create-new selection and
`0o666`/`0o600` permissions, reduced by umask. Public APIs, failure phases,
staging cleanup and synchronization order are unchanged.

Process capture closes each output pipe when it reaches EOF, using the absent
pipe as its completion state instead of retaining a descriptor and a separate
EOF flag. Capture still drains the other stream and waits for the selected
child disposition; limits, cancellation, observer output and cleanup remain
unchanged. No additional function, method or type is removed.

## 0.9.0

The Shared Tooling snapshot advances to committed 0.2.0
`8140e3dd1b44409d682c721889ab702f438c6a17`, retaining its 85-file selection.
The IC setup/check targets now select Quill, ICP CLI, didc, ic-wasm and wasm-opt.
PocketIC pin rows and shared installer branches are removed in favour of
[Testkit ownership](../ic-tools.md#pocketic-ownership-handoff)
([#38](https://github.com/dragginzgame/ic-host-tooling/issues/38),
[shared #76](https://github.com/dragginzgame/shared-tooling/issues/76)).

This breaks the developer setup contract, requiring a minor release before 1.0.
Run explicit `make install-ic-tools` to prepare the new selection before
`make ic-tools-check`; an old six-tool bundle is refused without execution or
automatic conversion. Setup preserves prior bundles, receipts and failed attempts.
Host library gates have no PocketIC consumer and gain no Testkit dependency.
Other repositories retain their own simulator adoption and qualification.

The remaining tool versions/digests, Rust library APIs and dependency selections
are unchanged. No Rust function, method or type is removed. The retired upstream
PocketIC checkers were never selected in this Host snapshot.
